# 새 기능 개발 시작: $ARGUMENTS

아래 순서로 진행한다. 각 단계마다 결과를 명확히 출력하고, 사용자 승인을 받는다.

## Step 1 — 웹 검색 (리서치)

`$ARGUMENTS`와 관련된 최신 베스트 프랙티스를 웹에서 검색한다.
- 구현 방법 2~3가지 옵션 검색
- 순수 HTML/JS/CSS 기반 구현 방법 우선 (이 프로젝트는 프레임워크 없음)
- iCal, Cloudflare Workers, 모바일 UX 관련 내용이 있으면 우선 포함
- 검색 결과를 요약하여 **"리서치 결과"** 섹션으로 출력

## Step 2 — 영향 범위 분석

`CLAUDE.md`와 `docs/` 를 참조하여:
- 어느 파일을 수정해야 하는가
- 청소 스케줄 앱과 예약현황 앱 둘 다 수정 필요한가
- `docs/05-known-issues.md` 의 체크리스트 중 해당 항목은 무엇인가
- 데이터 모델 변경이 필요한가 (기존 데이터 마이그레이션 여부)

## Step 3 — 스펙 초안 작성

`docs/features/` 디렉토리에 `DRAFT-<기능명>.md` 파일을 생성한다.

파일 형식:
```
# [기능명] 스펙

## 요약
한 줄 설명

## 목적 및 배경
왜 이 기능이 필요한가

## 기능 상세
- 사용자 시나리오 (어떤 상황에서 어떻게 쓰는가)
- UI/UX 설명
- 동작 규칙

## 기술 구현 방안
- 옵션 A: ...
- 옵션 B: ...
- 권장 방안 및 이유

## 영향 받는 파일
- 파일명: 변경 내용

## 데이터 변경
- 없음 / 있으면 상세 기술

## 제약 및 주의사항
- known-issues 관련 항목

## 미결정 사항 (사용자 확인 필요)
- ?
```

## Step 4 — 사용자에게 승인 요청

스펙 초안을 출력하고 다음을 물어본다:
1. 기능 방향이 맞는가?
2. 미결정 사항에 대한 결정
3. 구현 방안 선택 (옵션 여러 개일 경우)

**이 단계에서 멈추고 사용자 응답을 기다린다.**  
승인 없이 구현으로 넘어가지 않는다.
