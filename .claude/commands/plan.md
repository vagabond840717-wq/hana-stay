# 구현 계획 수립: $ARGUMENTS

`docs/features/DRAFT-$ARGUMENTS.md` (또는 사용자가 지정한 스펙 파일)를 기반으로 진행한다.

## Step 1 — 스펙 파일 확인

`docs/features/` 에서 관련 스펙 파일을 읽고, 승인된 내용을 바탕으로 계획 수립.

## Step 2 — 구현 계획서 작성

`docs/features/PLAN-<기능명>.md` 파일을 생성한다.

파일 형식:
```
# [기능명] 구현 계획

## 작업 단위 (순서대로)

### Task 1: [작업명]
- 파일: 파일경로
- 변경 내용: 구체적으로 무엇을 추가/수정/삭제하는가
- 예상 코드 라인: ~N줄

### Task 2: ...

## 변경 파일 목록
- [ ] 파일1 — 변경 이유
- [ ] 파일2 — 변경 이유

## 롤백 방법
만약 문제가 생기면 어떻게 되돌리는가

## 테스트 시나리오
구현 완료 후 검증할 항목들:
- [ ] 시나리오 1
- [ ] 시나리오 2

## 예상 주의사항
- known-issues 관련 항목
- 이벤트 등록 방식 (render() 후 attachCellClicks() 확인 등)
```

## Step 3 — 사용자에게 승인 요청

계획서를 출력하고 다음을 확인:
1. 작업 범위가 예상과 같은가?
2. 놓친 파일이나 엣지 케이스가 있는가?

**승인 받기 전에 코드 수정 시작하지 않는다.**

승인 후: `/implement $ARGUMENTS` 명령어로 구현 진행을 안내한다.
