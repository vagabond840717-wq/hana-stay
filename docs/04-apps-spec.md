## 1. 청소 스케줄 앱 (`app/JnJ/index.html`)

### 개요
- 타이틀: `HANA STAY · 청소 스케줄`
- 테마: 다크 (`--bg: #0f0f0f`)
- 목적: 청소 담당자가 보는 뷰. 체크인/아웃일과 도어락 비밀번호 관리.

### 헤더
- 앱 타이틀 (HANA STAY)
- 오늘 버튼 (`●`) — 현재 월로 이동
- 설정 버튼 (`☰`) — 호실 관리 패널 열기
- 월 네비게이션 (← 월 표시 →)
- 뷰 탭: **월간 | 주간 | 연속**

### Today Banner (상단 고정)
- 오늘 날짜 표시 (또는 마우스 호버/터치 선택일)
- 체크아웃 수 / 체크인 수 (모든 호실 합산)
- 동기화 버튼 (`↻`) — syncAll() 실행

### 달력 뷰 3종

#### 월간 뷰 (`renderMonth`)
- 현재 월부터 **6개월** 연속 표시 (가로 스크롤)
- 월 경계: 좌측에 굵은 세로선 + 월 라벨 행
- 호실별 행, 날짜별 열
- 오늘 셀: 하늘색 테두리 링
- PC 호버 / 모바일 롱프레스: 열 하이라이트 + 배너 갱신

#### 주간 뷰 (`renderWeek`)
- 현재 월을 주 단위로 분할 표시
- 각 주 하단: 청소 필요 날짜 카드 (체크아웃 호실 목록)

#### 연속 뷰 (`renderMulti`)
- 6개월을 각각 독립 테이블로 표시 (`renderMonthBlock` × 6)
- 월간 뷰와 달리 월별로 분리된 레이아웃

### 셀 인터랙션
- **클릭** → Detail Panel 오픈
- **PC 호버** → 열 하이라이트 + 배너 날짜 갱신
- **모바일 롱프레스(400ms)** → 열 하이라이트 시작
- **모바일 롱프레스 + 드래그** → 날짜 이동하며 배너 갱신

### Detail Panel (셀 클릭 시)
세 섹션으로 구성:

#### 예약 정보
- 체크인/아웃 날짜, 박수
- 플랫폼 배지 (✈/🏨/🌐/🏡)
- 역할 태그: **체크아웃** (주황) / **체크인** (초록) / **숙박중** (회색)
- 같은 날 여러 플랫폼 예약 시 모두 표시

#### 도어락 비밀번호
- 예약별 비밀번호 박스 (체크아웃/체크인 각각)
- 수정 버튼 → 인라인 입력 폼
- 삭제 버튼 (현재 비밀번호 제거)
- 이전 비밀번호 이력 (최대 14개 추가 표시)
- Enter 키로 저장

#### 메모
- 예약별 메모 입력 (textarea)
- `Ctrl+Enter` 또는 추가 버튼으로 저장
- 수정(✎) / 삭제(✕) 버튼
- 체크인/아웃이 동시인 날: 각 예약별 메모 좌우 분할 표시

### 호실 관리 패널 (`settingsPanel`)
- 호실 추가: 이름 + 4개 플랫폼 iCal URL
- 등록된 호실 목록 (최대 9개)
- 각 호실: 수정(✎) / 삭제(✕) 버튼
- 드래그앤드롭 순서 변경 (PC/모바일 모두)
- 수정 시 인라인 폼 (저장 즉시 iCal 재동기화)

### 동기화
- `syncAll()`: 모든 호실의 4개 플랫폼 iCal 동시 fetch
- 오류 무시 (Promise.all + 개별 try-catch)
- 완료 후 render() 호출
- ⚠ **청소앱은 `/bookings`를 쓰지 않는다.** `/?url=`로 iCal을 직접 받아 자기 파서로 판다.
  → 워커의 교정이 자동으로 닿지 않으므로, 트립만 `&fix=tr&room=<호실>` 옵트인을 붙인다 (2026.09.02, 아래 참조)

## 저녁 시간대 트립 날짜 교정 (두 앱 공통, 2026.09.02)

트립 `전략 제어 – 당일 객실 마감`이 매일 KST 18:00에 그날을 잠그고 07:00에 푼다. 그 가짜 하룻밤이
이웃 예약에 들러붙어 **저녁 6시 ~ 아침 7시 사이 인/아웃이 하루씩 어긋나 보인다** (known-issues #28).

**교정은 전부 워커에서 한다. 판정 로직은 워커 한 곳에만 있다** (#2 복제 방지).

| 앱 | 받는 경로 | 교정 |
|---|---|---|
| 예약현황 | `GET /bookings` | 자동 (**앱 코드 변경 없음**) |
| 청소 스케줄 | `GET /?url=…&fix=tr&room=<호실>` | `fetchTrIcal()` 한 줄 옵트인 |

- 청소앱의 다른 세 채널(`fetchIcal`·`fetchBkIcal`·`fetchLvIcal`)은 **손대지 않는다**
- `fix` 없는 `/?url=`은 **원본 그대로** — #28 판별 순서 1번("원본을 받아 대조")을 지키기 위함
- 데이터 구조·판정 규칙은 [03-data-model.md](03-data-model.md) `tr_daylock` 참조

## 2. 예약현황 앱 (`app/JnJ booking/index.html`)

### 개요
- 타이틀: `HANA STAY · 예약현황`
- 테마: 라이트 (`--bg: #f4f6fb`, 네이비 포인트)
- 목적: 예약 현황 전체 조회, 오버부킹/블락 감지

### 청소 스케줄 앱과의 차이점

#### 추가 기능
1. **오버부킹 감지** — 같은 호실 같은 날 두 개 이상의 예약 (플랫폼 무관)
   - 셀: `c-overbooking` (빨간 테두리)
   - 상단 배너: `ob-alerts` 섹션 (빨간 경고 배너)
   - **오늘 이전 날짜는 판정 제외** — 아카이브에 취소·변경된 옛 예약이 남아 오감지되기 때문 (known-issues #16)
   
2. **블락 처리** — Airbnb의 'blocked' 이벤트 구분
   - `c-ab-block`: Airbnb 블락 (회색)
   - `c-bl-block`: 기타 블락
   - `c-ab-block-checkin/checkout`: 블락+예약 복합
   - `c-dual` + `d1-*/d2-*`: 위 분기에 안 걸리는 복합 셀. 겹친 소스 색으로 상하 분할 (2026.08.05)

3. **달력 세로 스크롤** — `cal-scroll`에 `max-height` 제한 + `overflow-y: auto`
   - `thead { position: sticky; top: 0 }` — 날짜 행 고정

4. **PWA** — `<link rel="manifest" href="/manifest.json">`

5. **푸시 알림** — VAPID 공개키 설정됨
   ```js
   const VAPID_PUBLIC_KEY = 'BPRpwFw6g...';
   ```

#### 시각적 차이
| 요소 | 청소 스케줄 | 예약현황 |

## 3. 요금 계산기 (`app/JnJ Price/index.html`)

### 개요
- 타이틀: `HANA STAY — 요금 계산기 v8`
- 테마: 베이지 (`--bg: #F7F6F2`)
- 목적: 에어비앤비 기준 설정 후 타 플랫폼 동일 순수익 달성 가격 역산

### 입력 항목

#### Airbnb 기준
| 입력 | 기본값 | 설명 |
|------|--------|------|
| 수수료율 (%) | 15.5 | 2025.10~ 기본 |
| 프로모션 할인 (%) | 0 | 장기할인 등 |
| 주중 1박 요금 | 186,000 | |
| 주말 1박 요금 | 217,000 | |

#### 다른 플랫폼 역산
| 플랫폼 | 커미션율 기본값 | 프로모 기본값 |
|--------|--------------|-------------|
| Booking.com | 17.5% | 10% (Genius/모바일 합산) |
| Trip.com | 15% | 0% |
| 리브애니웨어 | 3.3% | 0% |

> 리브애니웨어는 역산이 아닌 에어비앤비 동일 등록가 기준 순수익 비교

#### 공통 설정
| 입력 | 기본값 |
|------|--------|
| 청소비 | 42,000 |
| 1인 추가요금 | 45,000 |
| 기준인원 | 2 |
| 최대인원 | 4 |

### 계산 로직

#### 실효 차감률
```js
effectiveRate(comm, promo) = promo/100 + (1 - promo/100) × comm/100
```

#### Airbnb 순수익
```js
extraAmt = (guests - baseG) × extraPerPerson
listed   = price + extraAmt
deduct   = listed × effectiveRate(fee, promo)
net1박   = listed - deduct - clean
net7박   = (listed - deduct) × 7 - clean
net30박  = (listed - deduct) × 30 - clean
```

#### 역산 (동일 순수익 달성 등록가)
```js
// 1박 기준
rate   = effectiveRate(comm, promo)
listed = (targetNet + clean) / (1 - rate)

// N박 기준
listed = (targetNetN + clean) / ((1 - rate) × N)
```

### 출력
- 플랫폼별 카드 형태
- 행: 주중/주말 × 기준인원~최대인원 조합
- 열: 등록가, 수수료·프로모, 청소비, 순수익(1박), 순수익(30박)
- 모바일: 테이블 → 카드형 반응형 전환

## 4. 주차 관리 (`app/parking-main/`)

### 개요
- Cloudflare Worker 기반 KV 저장소
- 프론트엔드는 `parking-main/index.html` (별도 구현)

### Worker API
```
GET  /kv?key=<key>       → { value: "..." }
POST /kv                 → { key, value } → { ok: true }
```

### 환경 변수
- `PARKING_KV`: Cloudflare KV 네임스페이스 바인딩
