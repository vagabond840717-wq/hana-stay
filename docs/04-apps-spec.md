## 1. 청소 스케줄 앱 (`app/JnJ/index.html`)

### 개요
- 타이틀: `HANA STAY · 청소 스케줄`
- 테마: 다크 (`--bg: #0f0f0f`)
- 목적: 청소 담당자가 보는 뷰. 체크인/아웃일과 도어락 비밀번호 관리.

### 헤더
- 앱 타이틀 (HANA STAY)
- 오늘 버튼 (`●`) — 현재 월로 이동
- 설정 버튼 (`☰`) — 호실 관리 패널 열기
- 월 네비게이션 (← 월 표시 →)
- 뷰 탭: **월간 | 주간 | 연속**

### Today Banner (상단 고정)
- 오늘 날짜 표시 (또는 마우스 호버/터치 선택일)
- 체크아웃 수 / 체크인 수 (모든 호실 합산)
- 동기화 버튼 (`↻`) — syncAll() 실행

### 달력 뷰 3종

#### 월간 뷰 (`renderMonth`)
- 현재 월부터 **6개월** 연속 표시 (가로 스크롤)
- 월 경계: 좌측에 굵은 세로선 + 월 라벨 행
- 호실별 행, 날짜별 열
- 오늘 셀: 하늘색 테두리 링
- PC 호버 / 모바일 롱프레스: 열 하이라이트 + 배너 갱신

#### 주간 뷰 (`renderWeek`)
- 현재 월을 주 단위로 분할 표시
- 각 주 하단: 청소 필요 날짜 카드 (체크아웃 호실 목록)

#### 연속 뷰 (`renderMulti`)
- 6개월을 각각 독립 테이블로 표시 (`renderMonthBlock` × 6)
- 월간 뷰와 달리 월별로 분리된 레이아웃

### 셀 인터랙션
- **클릭** → Detail Panel 오픈
- **PC 호버** → 열 하이라이트 + 배너 날짜 갱신
- **모바일 롱프레스(400ms)** → 열 하이라이트 시작
- **모바일 롱프레스 + 드래그** → 날짜 이동하며 배너 갱신

### Detail Panel (셀 클릭 시)
세 섹션으로 구성:

#### 예약 정보
- 체크인/아웃 날짜, 박수
- 플랫폼 배지 (✈/🏨/🌐/🏡)
- 역할 태그: **체크아웃** (주황) / **체크인** (초록) / **숙박중** (회색)
- 같은 날 여러 플랫폼 예약 시 모두 표시

#### 도어락 비밀번호
- 예약별 비밀번호 박스 (체크아웃/체크인 각각)
- 수정 버튼 → 인라인 입력 폼
- 삭제 버튼 (현재 비밀번호 제거)
- 이전 비밀번호 이력 (최대 14개 추가 표시)
- Enter 키로 저장
- **당일에만 공개** (2026.10.18) — 오늘(기기 날짜) 고른 칸의 **체크인·체크아웃 상자만** 번호·버튼·이력이 보인다.
  그 밖(앞날·지난날·숙박 중)은 `🔒 당일 공개` 만. 손으로 넣은 번호도 같은 규칙, 채널 무관 (`pwOpenToday`)
  - 이유: 비밀번호는 호스트와 손님만 안다. 청소 인력(알바, 사람이 바뀜)이 번호 세팅을 하므로 당일분만 필요
- **에어비앤비 자동 번호** (2026.10.18) — 손 입력이 없으면 손님 전화 끝 4자리를 크게 + `✈ 전화 끝 4자리 (자동)`
  - 에어비앤비 피드를 `fix=ab` 로 받는다 → 워커가 **오늘 입실·퇴실 예약 말고는 설명 줄을 지워 보낸다** (앞날 번호는 데이터로도 안 옴)
  - 상세: [features/airbnb-auto-pw.md](features/airbnb-auto-pw.md)

#### 청소 전용 링크 (2026.10.20, cleaner-link)
- 사장님이 보낸 **전용 링크**(`#k=…`)로 한 번 열면 폰이 기억한다. 맨 위 제목 옆에 이름이 작게 뜬다
- 링크는 **처음 연 폰 한 대**에 묶인다. 다른 폰·다른 브라우저(카톡 안 → 크롬 등)는 사장님 허용 전까지 대기
- 잠금이 켜져 있으면: 링크 없음 → "사장님께 받은 전용 링크로 열어 주세요" / 중지 → "사용이 중지됐어요" /
  대기 → "사장님 확인을 기다리는 중" / 거절 → "이 폰은 허용하지 않았어요" — 달력도 안 그린다
- 비밀번호는 **워커가** 오늘 체크인·체크아웃 서랍만 보내고 볼 때마다 기록. 자동 번호는 워커의 `auto`
- 달력은 `/feed?room=&ch=` 로 받는다 (원주소 모름). 링크 없이 열면 잠금 전까지는 예전 길
- **호실 관리(☰) 숨김** — 호실 추가·주소 수정·순서는 예약앱에서만. 기본 호실 자동 저장도 없앰
- 비밀번호는 폰에 남기지 않는다 (메모리에만). 시작할 때 옛 `hana_ex_*` 의 비밀번호와 `hana_rooms` 원주소를 지운다

#### 메모
- 예약별 메모 입력 (textarea)
- `Ctrl+Enter` 또는 추가 버튼으로 저장
- 수정(✎) / 삭제(✕) 버튼
- 체크인/아웃이 동시인 날: 각 예약별 메모 좌우 분할 표시

### 호실 관리 패널 (`settingsPanel`)
- 호실 추가: 이름 + 4개 플랫폼 iCal URL
- 등록된 호실 목록 (최대 9개)
- 각 호실: 수정(✎) / 삭제(✕) 버튼
- 드래그앤드롭 순서 변경 (PC/모바일 모두)
- 수정 시 인라인 폼 (저장 즉시 iCal 재동기화)

### 동기화
- `syncAll()`: 모든 호실의 4개 플랫폼 iCal 동시 fetch
- 오류 무시 (Promise.all + 개별 try-catch)
- 완료 후 render() 호출
- ⚠ **청소앱은 `/bookings`를 쓰지 않는다.** `/?url=`로 iCal을 직접 받아 자기 파서로 판다.
  → 워커의 교정이 자동으로 닿지 않으므로, 트립만 `&fix=tr&room=<호실>` 옵트인을 붙인다 (2026.09.02, 아래 참조)

## 저녁 시간대 트립 날짜 교정 (두 앱 공통, 2026.09.02)

트립 `전략 제어 – 당일 객실 마감`이 매일 KST 18:00에 그날을 잠그고 07:00에 푼다. 그 가짜 하룻밤이
이웃 예약에 들러붙어 **저녁 6시 ~ 아침 7시 사이 인/아웃이 하루씩 어긋나 보인다** (known-issues #28).

**교정은 전부 워커에서 한다. 판정 로직은 워커 한 곳에만 있다** (#2 복제 방지).

| 앱 | 받는 경로 | 교정 |
|---|---|---|
| 예약현황 | `GET /bookings` | 자동 (**앱 코드 변경 없음**) |
| 청소 스케줄 | `GET /?url=…&fix=tr\|bk&room=<호실>` | `fetchTrIcal()`·`fetchBkIcal()` 한 줄씩 옵트인 |

**워커가 하는 교정 세 가지** (판정 로직은 전부 워커 한 곳에만 — #2 복제 방지)

| | 무엇 | 채널 | 근거 |
|---|---|---|---|
| ① | 트립 당일잠금 가짜 하룻밤 제거 | `tr` | #28 |
| ② | 앞잘림 시작일 복원 | `bk` · `tr` | #29 |
| ③ | 오늘 퇴실 되살리기 | 네 채널 | #29 |

- 청소앱의 `fetchIcal`(에어비앤비)·`fetchLvIcal`(리브)은 **손대지 않는다** — 에어비앤비는 앞잘림을 안 한다
- `fix` 없는 `/?url=`은 **원본 그대로** — #28 판별 순서 1번("원본을 받아 대조")을 지키기 위함
- 데이터 구조·판정 규칙은 [03-data-model.md](03-data-model.md) `tr_daylock` 참조

## 2. 예약현황 앱 (`app/JnJ booking/index.html`)

### 개요
- 타이틀: `HANA STAY · 예약현황`
- 테마: 라이트 (`--bg: #f4f6fb`, 네이비 포인트)
- 목적: 예약 현황 전체 조회, 오버부킹/블락 감지

### 청소 스케줄 앱과의 차이점

#### 추가 기능
1. **오버부킹 감지** — 같은 호실 같은 날 두 개 이상의 예약 (플랫폼 무관)
   - 셀: `c-overbooking` (빨간 테두리)
   - 상단 배너: `ob-alerts` 섹션 (빨간 경고 배너)
   - **오늘 이전 날짜는 판정 제외** — 아카이브에 취소·변경된 옛 예약이 남아 오감지되기 때문 (known-issues #16)
   
2. **블락 처리** — Airbnb의 'blocked' 이벤트 구분
   - `c-ab-block`: Airbnb 블락 (회색)
   - `c-bl-block`: 기타 블락
   - `c-ab-block-checkin/checkout`: 블락+예약 복합
   - `c-dual` + `d1-*/d2-*`: 위 분기에 안 걸리는 복합 셀. 겹친 소스 색으로 상하 분할 (2026.08.05)

3. **달력 세로 스크롤** — `cal-scroll`에 `max-height` 제한 + `overflow-y: auto`
   - `thead { position: sticky; top: 0 }` — 날짜 행 고정

4. **PWA** — `<link rel="manifest" href="/manifest.json">`

5. **푸시 알림** — VAPID 공개키 설정됨
   ```js
   const VAPID_PUBLIC_KEY = 'BPRpwFw6g...';
   ```

#### 시각적 차이
| 요소 | 청소 스케줄 | 예약현황 |
|------|-----------|--------|
| 셀 배경 | 반투명 컬러 | 진한 단색 (`#22252e` 기본) |
| 체크아웃 색 | `rgba(240,179,91,0.22)` | `#e5503a` (선명한 빨강) |
| 체크인 색 | `rgba(110,207,143,0.22)` | `#1d9460` (선명한 초록) |
| 오늘 링 | 라임 그린 | `#38bdf8` (하늘색) |

6. **iCal 연결 오류 알림 자동 복구** (2026.06.11 추가)
   - 연결 오류(`error`) 알림이 미확인 상태에서 iCal 재연결 성공 시 자동 처리:
     - 해당 오류 알림 → 자동 확인됨(read: true)
     - `recovered` 이벤트 신규 생성 (✅ 초록 카드)
     - 폰에 "✅ {호실} 다시 연결됨" 푸시 알림 발송
   - 알림 패널 카드 색상: 아이콘·제목 `#166534`, 배경 `#f0fdf4`

7. **점유율 통계 뷰** (2026.06.08 추가)
   - 헤더 📊 버튼 탭 → 전체화면 통계 패널 전환
   - 오늘 기준 최근 12개월 × 호실별 점유율 그리드
   - 색상 강도: 연한 파랑(낮음) → 진한 네이비(높음) / 회색(데이터 없음)
   - 상단 탭: 전체 / ✈ Airbnb / 🏨 Booking / 🌐 Trip / 🏡 리브애니웨어 필터
   - 셀 탭 → "N박/M일 · Z%" 툴팁 표시
   - 마지막 행: 전체 평균 점유율
   - 데이터 소스: `/archive` 엔드포인트 (`booking_archive` KV)

8. **Trip.com 합쳐진 예약 경계 표시** (2026.07.01 추가 / 2026.08.06 `tr_cuts`로 구조 교체)
   - Trip.com이 연속 예약을 통짜 블락으로 합쳐 보내는 문제 보정 → 셀 클릭 시 상세에서 "손님이 바뀌는 날" 지정
   - 저장: `tr_cuts` — 날짜 하나만 기억 (→ [03-data-model.md](03-data-model.md))
   - 경계가 예약 한가운데일 때만 조각으로 치환. 겹침 없이 치환하므로 오버부킹으로 안 잡힘
   - 경계일은 `c-tr-both`(아웃/인 반반 + 🌐 아이콘)로 표시
   - **청소 스케줄 앱에도 자동 반영** (읽기전용 — 청소앱은 절대 쓰지 않음)
   - 예약이 연장·단축돼도 경계는 살아남는다. **자동 삭제 없음 — 사용자가 해지할 때만 사라진다**
     (2026.08.09 자동 은퇴 폐지. 트립 문의 날짜 들락날락에 경계가 영구 삭제되던 문제 → known-issues #27)
   - 상세: [features/booking-split.md](features/booking-split.md)

9. **경계 확인 알림 (⚠)** (2026.07.15 추가 / 2026.08.06 판정 방식 단순화)
   - 직전 피드 스냅샷(`tr_feed_prev`)과 비교해, **그 자리에 없던 예약이 새로 생겨 경계를 삼킨 경우**만 ⚠
   - 원래도 그 날짜를 덮던 예약이 합쳐진 것이면 정상 동작 → 조용히 통과
   - ⚠ 는 달력 셀 배지(`.attn-badge`, 3개 뷰 공통)로 표시 — 사용자가 확인할 때까지 유지 (토스트는 보조)
   - 경계를 지우거나 예약이 다시 나뉘면 자동 해제
   - 통신 실패 시 판정 보류 — 스냅샷·경계 데이터 보존
   - 판정·저장은 예약앱 전용 (청소앱은 결과 조각만 반영)
   - 상세: [features/split-inherit.md](features/split-inherit.md)

10. **점유율 그래프 뷰** (2026.07.21 추가)
    - 통계(점유율 탭) 상단에 12개월 평균 점유율 막대그래프 — 기본 선택은 이번 달
    - 막대 탭 → 요약 카드 4개(평균 점유율 / 객실당 평균 숙박 / 총 숙박(주중·주말 박수) / 주중·주말 점유율) + 호실별 가로 막대(주중=연한 파랑, 주말=진한 네이비 분리, 등록 순서)
    - 주말 = 금·토 밤 기준, 데이터는 기존 `booking_archive` 재사용(추가 KV 호출 없음)
    - 기존 12개월×호실 그리드는 그래프 아래에 그대로 유지
    - 상세: [features/occupancy-chart.md](features/occupancy-chart.md)

11. **예약 메모 표시** (2026.09.25 추가)
    - 메모 있는 예약은 연속·월간·주간 달력의 그 예약 칸마다 오른쪽 위 📝 (칸 색은 그대로)
    - 반반 칸은 메모 있는 손님 쪽 반에만. 나가는 손님이면 칸 가운데 위. 오버부킹 ⚠ 칸에는 안 붙임
    - 예약 상세의 메모 칸을 **손님별로** 나눔 (아웃 손님 / 인 손님). 메모마다 머리표 `✈/🏨/🌐/🏡/🔒 + 날짜`
    - 청소앱: 📝 달력 표시는 없음, 메모 머리표만. 청소앱에서 쓴 메모도 예약앱 📝 에 반영
    - 메모는 퇴실 30일 뒤 자동 삭제 (비밀번호는 남음)
    - 상세: [features/memo-indicator.md](features/memo-indicator.md)

12. **비밀번호 삭제** (2026.10.01 추가) — 청소앱과 같은 동작
    - 지금 번호 옆 `삭제` → 지금 번호를 지우고 **바로 전 번호가 지금 번호로 올라옴**. 번호가 없으면 버튼 안 보임

> 리브애니웨어는 역산이 아닌 에어비앤비 동일 등록가 기준 순수익 비교

#### 공통 설정
| 입력 | 기본값 |
|------|--------|
| 청소비 | 42,000 |
| 1인 추가요금 | 45,000 |
| 기준인원 | 2 |
| 최대인원 | 4 |

### 계산 로직

#### 실효 차감률
```js
effectiveRate(comm, promo) = promo/100 + (1 - promo/100) × comm/100
```

#### Airbnb 순수익
```js
extraAmt = (guests - baseG) × extraPerPerson
listed   = price + extraAmt
deduct   = listed × effectiveRate(fee, promo)
net1박   = listed - deduct - clean
net7박   = (listed - deduct) × 7 - clean
net30박  = (listed - deduct) × 30 - clean
```

#### 역산 (동일 순수익 달성 등록가)
```js
// 1박 기준
rate   = effectiveRate(comm, promo)
listed = (targetNet + clean) / (1 - rate)

// N박 기준
listed = (targetNetN + clean) / ((1 - rate) × N)
```

### 출력
- 플랫폼별 카드 형태
- 행: 주중/주말 × 기준인원~최대인원 조합
- 열: 등록가, 수수료·프로모, 청소비, 순수익(1박), 순수익(30박)
- 모바일: 테이블 → 카드형 반응형 전환

## 4. 주차 관리 (`app/parking-main/`)

### 개요
- 저장소 `vagabond840717-wq/parking` — 프론트는 **GitHub Pages** (루트 `index.html`), 백엔드는 Cloudflare Worker
- Cloudflare Worker 기반 KV 저장소
- 프론트엔드는 `parking-main/index.html` (별도 구현)

### Worker API
```
GET  /kv?key=<key>       → { value: "..." }
POST /kv                 → { key, value } → { ok: true }
```
워커는 **KV 통과용일 뿐 날짜 로직이 없다** → 날짜 관련 문제는 전부 `index.html` 쪽이다.

### 환경 변수
- `PARKING_KV`: Cloudflare KV 네임스페이스 바인딩

### 데이터 구조
```js
// KV: parking_data  (WORKER_URL/kv?key=parking_data)
{ "L2-2": [ { room:"302", car:"384누 8008", start:"2026-09-09", end:"2026-09-10",
              contact:"", memo:"" }, ... ] }   // 슬롯당 배열, 여러 예약 보관
// 자리 10개: L1(2) · L2(2) · L3(3) · L4(3).  outer=바깥 / inner=안쪽(이중주차)
```
- `end` 는 **exclusive** — `start <= 날짜 && end > 날짜` 일 때만 그 날 주차 중
  (`getActiveResvOnDate`). `end === 오늘` = **오늘 출차하는 날** → 배너가 이걸 읽는다

### ⚠ 날짜는 반드시 기기 로컬 기준 (2026.09.09)
```js
function ymd(dt){ return `${dt.getFullYear()}-${String(dt.getMonth()+1).padStart(2,'0')}-${String(dt.getDate()).padStart(2,'0')}`; }
function todayStr(){ return ymd(new Date()); }
```
- **`toISOString()` 을 날짜 문자열로 쓰지 말 것** — UTC로 바뀌어 KST 자정~오전 9시에 하루 밀린다.
  예약앱 `today()`·청소앱 `today()`와 동일한 로컬 방식으로 통일했다 ([#30](05-known-issues.md))
- `new Date('YYYY-MM-DD')` 도 **UTC 자정 파싱**이다 → 날짜 이동은 연·월·일을 분해해 `new Date(y, m-1, d)`
- **KST 하드코딩 금지** — 세 앱이 같은 시계를 봐야 화면끼리 어긋나지 않는다
- `autoExpire()` 는 `end >= todayStr()` — **지난 예약만** 지운다. 오늘 출차분은 배너가 쓰므로 남긴다
