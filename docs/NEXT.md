# 🔍 사장님이 "이거 왜 이래?" 하면 — Claude 가 먼저 확인할 순서

> 사장님은 세이브 포인트를 직접 안 본다. **증상만 말한다.** 이 절은 Claude 가 바로 원인을 찾으려고 적어두는 곳이다.
> 새로 알게 된 확인법·판별 규칙은 **여기에 계속 덧붙인다.**

**0. 화면이 '배포본'인지부터** — 예약앱은 GitHub Pages 캐시 10분. 고친 지 10분 안이면 옛 화면일 수 있다.
   사장님 스크린샷의 기준시각(`2026.10.05 17:52 기준`)과 배포 시각을 비교.

**1. 원본 피드 — 채널이 실제로 뭘 보내나** (이게 진실. 앱·워커 가공 전)
```bash
W=https://ical-proxy.vagabond1984.workers.dev
u=$(curl -s $W/rooms | grep -o '"name":"402 jnj","url":"[^"]*"' | cut -d'"' -f8)   # bkUrl·trUrl 도 같은 식
curl -s "$W/?url=$(printf %s "$u" | sed 's/:/%3A/g;s/\//%2F/g;s/?/%3F/g;s/=/%3D/g;s/&/%26/g')" | grep -A5 DTSTART
```
   에어비앤비는 `DESCRIPTION` 에 **예약번호(HM…)·전화 끝 4자리**가 있다 → 두 칸이 같은 손님인지 바로 판별
   (10/05 402호 10/9~10/10 · 10/10~10/19 = 번호 다름 → 진짜 교대였다)

**2. 언제 생기고 사라졌나** — `curl -s "$W/changes?room=402%20jnj&ch=ab&limit=40"` (9/22~, ts 는 ms, KST = +9h)
   - 기록에 한 줄도 없는데 화면에 있다 → 피드에서 온 게 아니다 → 수첩(아카이브)에서 나온 유령 의심
   - 입실 **전에** `out` → 취소 (예: 402 트립 10/1~10/4 가 10/1 04:20 out)

**3. 그 밤에 실제로 있었나** — `curl -s "$W/ledger?from=2026-09&to=2026-10"` (장부, 9/21~)
   - 방·날짜 칸이 `{}` = **그 밤 비어 있었음이 확정**. 칸이 아예 없음 = 모름
   - ⚠ **부킹·트립 밤은 장부에 빠진다** (자정 앞잘림 뒤 07:30 에 굳힘). 부킹·트립은 장부로 판단 금지

**4. 수첩·화면 재료** — `/archive`(한 번이라도 본 모든 모양, 시각 없음) · `/bookings`(예약앱이 받는 것, 워커 가공 후)

**채널별로 끝난 예약이 피드에서 빠지는 시각** (feed_changes 실측) — 유령 판별의 핵심
