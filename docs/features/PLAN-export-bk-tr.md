## 작업 단위 (순서대로)

### Task 1: 배포 전 예행연습 (코드 수정 없음)
- 파일: 없음 — 스크래치패드에 임시 스크립트
- 내용: 실제 피드 5개를 받아 **새 필터를 적용했을 때 어떤 결과가 나오는지 미리 표로 출력**한다. 운영에는 아무 영향 없음
- 목적: 배포 후에야 알게 되는 사고 방지. 특히 "빠지면 안 될 예약이 빠지는지" 확인
- 예상 코드: ~40줄 (임시, 커밋 안 함)

### Task 2: 상수·헬퍼 추가
- 파일: `ical-proxy/worker.js` — `exportIcal()` 바로 위
- 변경 내용:
  ```js
  // 부킹닷컴·트립닷컴은 실제 예약과 '판매 미오픈 기간'의 제목이 완전히 같다.
  // (bk: 둘 다 "CLOSED - Not available" / tr: 둘 다 "RoomStatus Fully booked")
  // 두 채널은 오늘부터 6개월까지만 판매를 열어두므로, 그 범위 밖에서 끝나는 항목은
  // 실제 예약일 수 없다 = 전부 미오픈 기간. 날짜가 고정이 아니라 매일 같이 굴러간다.
  const OPEN_MONTHS_BK_TR = 6;
  const GRACE_DAYS = 7;   // 채널이 월말 단위로 끊는 등 미세하게 더 열어줄 여지

  const dayMs = (y, m, d) => Date.UTC(y, m, d);

  // 워커는 UTC로 도는데 숙소는 한국 → 9시간 보정해서 '한국 기준 오늘 0시'를 구한다
  function todayKST() {
    const n = new Date(Date.now() + 9 * 3600 * 1000);
    return { y: n.getUTCFullYear(), m: n.getUTCMonth(), d: n.getUTCDate() };
  }
  ```
- `exportIcal()` 진입부에서 한 번만 계산:
  ```js
  const t = todayKST();
  const today   = dayMs(t.y, t.m, t.d);
  const horizon = dayMs(t.y, t.m + OPEN_MONTHS_BK_TR, t.d + GRACE_DAYS);  // Date.UTC가 월/일 넘침을 알아서 보정
  ```
- 예상 코드: ~12줄

### Task 3: `exportIcal()` 필터를 플랫폼별로 분리
- 파일: `ical-proxy/worker.js` — [worker.js:450](../../ical-proxy/worker.js) 한 줄을 세 줄로 교체
- 변경 전:
  ```js
  if (bk.summary?.toLowerCase().includes('not available')) continue;
  ```
- 변경 후:
  ```js
  // ① 에어비앤비가 준 블락을 되돌려주면 무한 반복 → 제외 (제목으로 구분되는 유일한 채널)
  if (key === 'ab' && bk.summary?.toLowerCase().includes('not available')) continue;
  // ② 부킹·트립: 판매 오픈 범위(오늘+6개월) 밖에서 끝나면 실제 예약일 수 없다 → 제외
  //    체크아웃 기준. 체크인 기준이면 경계 안쪽에서 시작해 한참 뒤까지 뻗는 꼬리를 놓친다
  //    (402호 트립 2027-01-01~06-15가 그 사례). 리브애니웨어는 대상 아님
  if ((key === 'bk' || key === 'tr')
      && dayMs(bk.coutY, bk.coutM, bk.coutD) > horizon) continue;
  // ③ 이미 지난 예약은 오버부킹이 날 수 없다 → 내보내지 않음 (오늘 체크아웃은 유지)
  if (dayMs(bk.coutY, bk.coutM, bk.coutD) < today) continue;
  ```
- `const today = todayKST();`는 반복문 밖에서 한 번만 계산
- **`ds` / `de` 생성부는 한 글자도 건드리지 않는다** (알려진이슈 #21)
- 예상 코드: ~8줄

### Task 4: 수동 블락에도 과거 제외 적용
- 파일: `ical-proxy/worker.js` — `exportIcal()` 의 `extra_manual_blocks` 반복문
- 변경 내용: 종료일이 오늘보다 이전인 수동 블락은 건너뛴다
  ```js
  if (dayMs(bl.endY, bl.endM, bl.endD) < today) continue;
  ```
- 근거: 402호 내보내기에 `Blocked 20260704~20260719` (지난 7월)가 아직 나가고 있음
- 수동 블락의 `endDate + 1` 계산은 **그대로 유지** (수동 블락만 마지막 날 포함 규칙)
- 예상 코드: ~1줄

### Task 5: 배포
- `ical-proxy` 저장소에 커밋 → push → Cloudflare 자동 배포
- 커밋 메시지: `fix: 부킹·트립 예약 내보내기 누락 수정 + 미오픈 기간·과거 예약 제외`

### Task 6: 동기화 1회 실행
- `POST /sync` 호출
- 이유: 내보내기는 KV에 저장된 데이터를 읽는다. 지금 저장본이 실제 피드보다 뒤처져 있어(603호 꼬리 기준 약 한 달) 배포만으로는 최신 결과가 안 나온다

### Task 7: 결과 검증
- 호실 5개 `/ical/` 전부 다시 받아 Task 1 예행연습 결과와 대조

## 롤백 방법

1. `ical-proxy` 저장소에서 직전 커밋으로 되돌리고 push → 자동 재배포 (약 1분)
2. 더 급하면 Cloudflare 대시보드 → Workers → ical-proxy → Deployments → 이전 버전 Rollback (즉시)

되돌리면 부킹 예약이 다시 안 나가는 상태로 복귀할 뿐, **데이터가 망가지지는 않는다.** KV를 건드리지 않기 때문.

## 예상 주의사항

- ⚠ **전 채널 즉시 영향.** 에어비앤비·부킹닷컴·리브애니웨어가 이 주소를 구독한다
- ⚠ **알려진이슈 #21** — `DTEND`에서 하루를 빼면 안 된다. 이번 변경은 `ds`/`de` 라인을 아예 건드리지 않음
- ⚠ **알려진이슈 #8** — `cinM`/`coutM`은 0-indexed. `Date.UTC(y, m, d)`에 그대로 넣으면 맞다
- 에어비앤비는 가져온 블락을 자기 iCal로 되내보내지 않는다 → 반영 여부는 앱 달력 화면으로만 확인 가능
- ⚠ **판매 오픈 기간을 6개월에서 바꾸면 `OPEN_MONTHS_BK_TR`도 같이 바꿔야 한다.** 기준선이 실제 오픈 범위보다 짧으면 진짜 예약이 안 나가 오버부킹, 길면 가짜 꼬리가 새어나가 헛되이 닫힘
- 에어비앤비(3개월)는 별도 기준선을 두지 않는다. 제목(`Reserved` vs `Not available`)으로 이미 구분되고, 실제 예약은 어차피 3개월 안에만 존재하므로 날짜 판정이 불필요하다
- 렌더/이벤트 등록(`render()` → `attachCellClicks()`)은 앱 코드라 이번 변경과 무관
