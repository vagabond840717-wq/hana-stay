# 예약 메모 표시 스펙 (DRAFT)

## 요약
메모가 있는 예약은 예약앱 달력의 그 예약 칸마다 오른쪽 위에 작은 📝 를 붙인다.

## 목적 및 배경
예약 상세에 메모(예: 601 jnj 10/20~10/28 "아기침대 요청")를 적어도 달력에서는 안 보여서, 상세를 하나하나 열어봐야 알 수 있다.

## 결정 사항 (사장님 확인 2026-09-24)
| # | 내용 |
|---|---|
| 1 | 📝 는 **예약앱만**. 연속·월간·주간 전부. 칸 오른쪽 위, 칸 색은 그대로 (샘플대로) |
| 2 | 반반 칸(아웃/인)은 메모 있는 손님 쪽 반에만 📝 (나가는 손님 쪽이면 칸 가운데 위). 예약 상세의 메모 칸도 **손님별로** 나눈다 |
| 3 | 에어비앤비는 **예약 번호(iCal UID)** 로 연결 → 날짜가 바뀌어도 따라간다. 부킹·트립·리브·블락은 **호실+체크인 날짜** (부킹은 UID 를 매일 새로 발급한다는 보고) |
| 4 | 예약이 사라지면 📝 만 바로 숨긴다. **메모는 남긴다** — 다시 나타나면 📝 도 다시 (#27 교훈) |
| 5 | 메모 자동 삭제: **모든 채널, 체크아웃 30일 뒤**. 비밀번호는 남긴다. 사람이 손으로 정리할 필요 없음 |
| 6 | **메모 한 줄마다 머리표**: `아이콘 + 예약 날짜`만. 글자 없이 짧게 — 예) `🏨 10/20~10/28`. 아이콘 ✈ 에어비앤비 / 🏨 부킹 / 🌐 트립 / 🏡 리브 / 🔒 블락. **메모를 쓴 순간의 예약으로 고정**된다. 어느 채널 예약 메모인지 보고 찾아본 뒤 필요 없으면 지우려는 것 |
| 7 | 청소앱에서도 메모가 보인다. 지금 청소앱에 안 보이는 부킹·트립·리브 메모도 이번에 보이게 맞춘다 (서랍 이름 통일 + 기존 데이터 이관) |
| 8 | 코딩 전에 에어비앤비 UID 가 날짜 변경 뒤에도 그대로인지 실측. 아니면 에어비앤비도 날짜 연결 |

## 지금 코드 (조사 결과 — 예약앱 `c21b0d9`, 청소앱 `6b5cbf6`, 워커 `9709111`)
- 메모·비밀번호는 한 서랍 `extra_<호실>|<YYYYMMDD 입실일>` 에 같이 있다. localStorage 사본 + KV
- 예약앱 `openDetail` 은 그 칸의 **맨 앞 예약 하나(`allBks[0]`)** 서랍만 연다 → 반반 칸에서 나가는 손님에게 붙을 수 있음
- 예약앱은 채널 꼬리표를 **안 붙인다**. 청소앱은 부킹·트립·리브에 `_bk/_tr/_lv` 를 붙인다
  → 에어비앤비 외엔 두 앱이 **다른 서랍**을 본다 (비밀번호·메모 모두)
- 워커 `parseIcal` 이 UID 를 버린다
- 메모를 지우는 규칙은 어디에도 없다

## 기술 구현 방안 (초안 — /plan 에서 확정)
- 메모 한 줄에 채널·예약 날짜를 같이 저장한다: `{text, date, ch, cin, cout}` (머리표 표시용. 옛 메모는 서랍 이름에서 채널·입실일을 복원, 퇴실일 모르면 입실일만)
- **메모 목록** `extra_memo_index` 하나를 둔다: `[{room, ch, cin, cout, uid?, key}]`
  - 달력은 이것만 한 번 읽어 📝 를 그린다 (칸마다 서버에 묻지 않음)
  - 공유 목록이므로 반드시 `saveListMerged` 경유 (#22·#26)
- 워커: `parseIcal` 이 에어비앤비 UID 를 예약에 실어 보낸다. `exportIcal` 무영향
- 에어비앤비 날짜 변경: 번호는 같은데 입실일이 다르면 메모를 새 서랍으로 옮기고 목록을 고친다
- 30일 정리: 워커 cron 하루 1회. 목록에서 `cout+30 < 오늘` 인 줄 → 서랍의 memos 만 비우고 줄 삭제

## 구현 전에 확인할 것
- [ ] **에어비앤비 UID 가 날짜 변경 뒤에도 그대로인지** 실측 (웹 검색으로는 확인 못 함). 안 그대로면 에어비앤비도 날짜 연결로 후퇴
- 참고: 부킹닷컴은 UID 를 매일 새로 발급한다는 보고가 있다 (github.com/Giginoparrucca/doorstep PR #41)
