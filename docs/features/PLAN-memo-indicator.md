## 핵심 설계 한 장

```
서랍 (지금 그대로 — 두 앱이 같이 봄)          메모 목록 (새로 — 달력 📝 용)
extra_<호실>|<입실일>        ← 에어비앤비       extra_memo_index
extra_<호실>|<입실일>_bk     ← 부킹            [{key, room, ch, cin, cout, uid?}]
extra_<호실>|<입실일>_tr     ← 트립             · 메모가 1개 이상 있는 서랍만 한 줄
extra_<호실>|<입실일>_lv     ← 리브             · 달력은 이것 하나만 읽는다
extra_<호실>|<시작일>_bl     ← 블락 (새 꼬리표)  · 공유 목록 → saveListMerged 필수 (#22·#26)

메모 한 줄: {text, date, ch, cin, cout}   ← ch·cin·cout 이 머리표(🏨 10/20~10/28). 쓴 순간 고정
```

- **연결 규칙**: 에어비앤비는 `uid` 가 맞으면 그 예약, 아니면 `호실+채널+입실일`. 나머지는 `호실+채널+입실일`만.
  → UID 가 불안정해도 **날짜 연결로 자연히 후퇴**한다. 그래서 UID 실측이 구현을 막지 않는다
- 에어비앤비 날짜 변경: 같은 `uid` 가 다른 입실일로 나타나면 워커가 서랍을 새 입실일로 옮긴다
- 📝 판정은 **지금 화면에 있는 예약**과 목록을 맞춰 본다 → 예약이 사라지면 📝 는 저절로 안 뜬다. 메모는 그대로
