# 청소 전용 링크 스펙

## 요약
청소 인력마다 전용 링크를 카톡으로 보내고, 그 링크로만 청소앱이 열린다. 비밀번호를 볼 때마다
**누가·어느 방·언제**가 기록되고, 사장님은 예약앱에서 기록을 본다. 앱을 거치지 않는 뒷문도 같이 잠근다.

## 목적 및 배경
- 10/18 '에어비앤비 비번 자동'으로 청소앱은 **당일분만** 비밀번호를 보여준다.
- 그래도 청소 인력이 번호를 세팅하므로 외워 두었다가 손님이 없을 때 들어가는 **도난 위험**이 남는다 (사장님, 10/19).
- 마스터키는 사장님만 쓴다. 도어락 원격 세팅은 지금 없음.
- 대책: **누가 봤는지 기록이 남으면** 함부로 못 한다. 개인 번호 입력은 번거로우니 **사람별 전용 링크**로 (사장님 결정 10/19).
- 그런데 앱 앞문에만 기록을 두면 뒷문으로 보는 사람은 기록에 안 남는다 → [#38](../05-known-issues.md) 을 같이 막아야 의미가 있다.

### 지금 열려 있는 뒷문 (10/19 확인)
| 길 | 무엇이 보이나 | 누가 쓰나 |
|---|---|---|
| `GET /rooms` | 4채널 달력 **원주소** → 에어비앤비 원본에 앞날 손님 전화 끝 4자리 전부 | 두 앱 |
| 청소앱 **호실 관리 화면** | 같은 원주소를 화면에서 보고 고칠 수 있음 (`saveRooms` → `POST /rooms`) | 청소앱 |
| `GET /bookings` | 예약앱용 `ph` (전화 끝 4자리) 전부 | 예약앱 |
| `GET /extra?key=<호실>\|<입실일>` | 손으로 넣은 비밀번호 (날짜 무관) | 두 앱 |
| 청소 인력 **휴대폰 저장소** | 예전에 받은 원주소(`hana_rooms`) · 열어본 비밀번호(`hana_ex_*`) | 청소앱 |
- 요금 계산기·주차 앱은 워커를 안 쓴다 (확인함) → 영향 없음

## 기능 상세

### 사용자 시나리오
1. **사장님이 링크 만들기** — 예약앱 ⚙ → `청소 링크` → `새 링크` → 이름 "김민수" → `카톡으로 보내기`
   (휴대폰 공유창 → 카톡 선택). 링크 예: `https://jnjhana.pages.dev/#k=Xq3…`
2. **김민수가 링크를 한 번 연다** → 청소앱이 열쇠를 휴대폰에 기억하고 주소창에서 지운다.
   그 뒤로는 홈 화면 아이콘이든 그냥 주소든 **입력 없이** 열린다.
3. **10/19 402호 교대 칸을 누른다** → 나가는·들어오는 손님 번호가 보인다 → 워커가 기록:
   `10/19 10:12 김민수 · 402호 들어오는 손님 · 봄`
4. **도어락을 바꾸고 번호를 입력** → `10/19 10:30 김민수 · 402호 들어오는 손님 · 바꿈 5555`
5. **사장님이 예약앱에서 기록 확인** — ⚙ → `열람 기록` (최신이 위)
6. **김민수가 그만둠** → 사장님이 명단에서 `중지` → 김민수 폰의 청소앱은 "사용이 중지됐어요" 만 보인다. 그 시도도 기록.
   다시 일하면 `다시 허용`
7. 링크 없이 그냥 `jnjhana.pages.dev` 로 들어온 사람 → "사장님께 받은 전용 링크로 열어주세요"
8. **김민수가 링크를 친구에게 넘김** → 친구 폰에서는 안 열린다 ("사장님 확인을 기다리는 중").
   명단에 `김민수 링크로 다른 폰이 들어오려 함` → 사장님이 `허용`(폰을 바꾼 경우) / `거절`

### 링크는 처음 연 폰 한 대에 묶인다 (사장님 결정 10/19)
- 링크를 처음 연 폰이 그 사람의 폰이 된다. 다른 폰은 사장님이 허용해야 열린다 → **기록의 이름 = 실제로 본 사람**
- 폰 구분은 청소앱이 처음 열 때 만든 무작위 기기 번호로 한다 (웹 앱은 전화번호·기기 주인을 알 수 없다)
- ⚠ **같은 폰이라도 브라우저가 바뀌면 다른 폰으로 보인다.** 카톡에서 링크를 누르면 카톡 안 브라우저로 열리고,
  나중에 크롬·사파리로 열면 '새 폰'이 된다. 폰 저장소를 지워도 마찬가지 → 사장님이 `허용` 한 번이면 해결.
  링크 보낼 때 "카톡에서 열린 화면 오른쪽 위 메뉴 → 다른 브라우저로 열기 → 홈 화면에 추가" 안내문을 같이 보낸다

### 화면
- **예약앱 ⚙ `청소 인력 명단`**: 사람마다 한 줄 — 이름 · 상태(`일하는 중`·`새 폰 확인 필요`·`중지됨`) ·
  마지막 접속 · 쓰는 폰(기종) · 이번 달 열람 횟수 · `중지`/`다시 허용` · 새 폰이면 `허용`/`거절` · `링크 다시 보내기`.
  맨 아래 `새 사람 추가` (이름 → 링크 만들기 → `카톡으로 보내기`)
- **예약앱 ⚙ `열람 기록`**: 시각 · 이름 · 방 · 나가는/들어오는 손님 · 봄/바꿈/지움/거절. 이름으로 거르기
- **청소앱**: 지금 화면 그대로 + 맨 위 작게 `김민수` (누구로 열렸는지). **호실 관리 화면은 없앤다** (미결정 2)

### 동작 규칙
1. 열쇠 2종 — **사장님 열쇠**(예약앱, 전부) / **청소 열쇠**(사람별, 당일분만)
2. 비밀번호 판정은 **워커가 한다** (한국 날짜). 앱 화면 규칙은 보조일 뿐
3. 청소 열쇠로 보이는 것: 오늘 체크인·체크아웃하는 예약 서랍의 비밀번호 + 에어비앤비 자동 번호. 그 밖은 빈칸
4. 보여줄 때마다·바꿀 때마다 기록. 같은 사람·같은 서랍을 10분 안에 다시 열면 한 줄로 친다 (저장 쓰기 절약)
5. 꺼진 열쇠·없는 열쇠로 온 요청은 **거절 + 기록** (같은 열쇠는 하루 1줄만)
6. 기록은 앱에서 지울 수 없다 (사장님 예약앱도 보기만). 최근 90일·5,000줄

## 기술 구현 방안

### 옵션 A — 사람별 링크 + 워커가 판정·기록 (권장)
- 링크의 열쇠는 주소 `#` 뒤에 둔다 → 서버·중간 기록에 주소가 안 남는다 ([W3C 권고](https://www.w3.org/2001/tag/doc/capability-urls), [fragment 설명](https://docs.vdo.ninja/help/privacy-and-security-details/fragment-url-parameters))
- 앱은 열쇠를 휴대폰에 저장하고 모든 워커 요청에 `X-Hana-Key` 머리글로 붙인다
- 워커는 열쇠 목록(KV)에서 사람을 찾고, 비밀번호가 나가는 길마다 검사 ([Cloudflare 머리글 인증 예시](https://8f23c8e1.previews.developers.cloudflare.com/workers/examples/auth-with-headers/index.md))
- 👍 앱을 우회해도 열쇠 없으면 못 봄 / 기록이 서버에 남아 지울 수 없음 / 링크 끄면 즉시 차단
- 👎 두 앱 + 워커를 같이 바꾸는 큰 작업. 배포 순서를 잘못 잡으면 **사장님도 잠긴다** (아래 순서 참고)

### 옵션 B — 앱 화면에서만 기록
청소앱이 비밀번호를 보여줄 때 스스로 기록을 보낸다. 워커는 그대로.
- 👍 작다
- 👎 앱을 거치지 않으면 기록도 없다 = 사장님이 막으려는 사람을 못 막음. **권장 안 함**

### 옵션 C — Cloudflare Access (이메일 로그인)
청소 인력이 이메일로 받은 숫자를 넣어 로그인. 무료(50명). 기록은 Cloudflare 가 남긴다.
- 👍 가장 단단함
- 👎 주기적으로 이메일 로그인 → 사장님이 원하지 않은 '입력' 방식

### 워커에서 바뀌는 길
| 길 | 사장님 열쇠 | 청소 열쇠 | 열쇠 없음 |
|---|---|---|---|
| `GET /rooms` | 그대로 | **원주소 4개 빈칸** | 빈칸 (미결정 1) |
| `POST /rooms` | 그대로 | **거절** | 거절 |
| `GET /feed?room=&ch=` (새) | — | 워커가 저장된 주소로 받아 교정(`fix`)·**설명 줄 전부 삭제** | 거절 (미결정 1) |
| `GET /bookings` | 그대로 (`ph` 포함) | `ph` 뺌 | `ph` 뺌 |
| `GET /extra?key=<서랍>` | 그대로 | 당일 체크인·체크아웃 서랍만 비밀번호 + 자동 번호(`auto`) → **기록** | 비밀번호 빈칸 |
| `POST /extra` (서랍) | 그대로 | 당일 서랍만 비밀번호 저장 → **기록**. 그 밖은 서버 비밀번호 **보존** | 비밀번호 **보존** |
| 공유 목록(`manual_blocks`·`tr_cuts`·`memo_index` 등) | 그대로 | 그대로 | 그대로 |
| `/ical/…` 내보내기 · `/archive` · `/changes` · `/ledger` · `/push/*` | 무영향 (번호 없음) | | |
- ⚠ **`POST /extra` 보존이 핵심**: 비밀번호를 빈칸으로 받은 앱이 메모만 고쳐 저장하면 지금 구조로는 **비밀번호가 지워진다**. 워커가 막는다
- `fix=ab` (10/18) 는 `/feed` 로 대체 → 청소앱이 더는 원주소를 몰라도 된다

## 영향 받는 파일
| 파일 | 변경 |
|---|---|
| `ical-proxy/worker.js` | 열쇠 확인 · 위 표의 길 · `/feed` · 기록 쓰기/읽기(`/access/log`) · 링크 관리(`/access/links`) · CORS 에 `X-Hana-Key` |
| 예약앱 `index.html` | 사장님 열쇠 저장·첨부 · ⚙ `청소 링크` · ⚙ `열람 기록` · `/bookings`·`/extra`·`/rooms` 요청에 머리글 |
| 청소앱 `index.html` | `#k=` 읽어 저장·주소창 정리 · 모든 요청에 머리글 · 피드를 `/feed` 로 · 호실 관리 제거 · 옛 저장분(`hana_rooms` 원주소·`hana_ex_*` 비밀번호) 지우기 · 열쇠 없음/꺼짐 안내 화면 |

## 데이터 변경
| 저장소 | 내용 |
|---|---|
| KV `access_links` (새, `extra_` 아님) | `[{id, name, key(해시), on, created, lastUsed, devices:[{dev(해시), ua, first, ok}], pending:[{dev, ua, ts}]}]` — 열쇠·기기 번호는 **해시로만** 저장. `lastUsed` 는 하루 1번만 갱신 |
| KV `access_log` (새) | `[{ts, who, name, room, drawer, role:"in"\|"out", act:"view"\|"set"\|"del"\|"deny", pw?}]` 5,000줄·90일 |
| 워커 비밀 `OWNER_KEY` | 사장님 열쇠. Cloudflare 설정 화면에 저장 (코드·KV 에 안 둠) |
- 기존 데이터 마이그레이션 없음. 서랍(`extra_*`) 모양 그대로

## 배포 순서 (사장님이 잠기지 않게)
1. 워커: 열쇠를 **받기만** 하고 아무것도 막지 않는 판 + 링크 관리·기록
2. 예약앱: 사장님 열쇠 붙이기 + 링크 관리 화면 → 사장님 열쇠 링크로 한 번 열기
3. 청소앱: 열쇠 붙이기·`/feed`·호실 관리 제거 → 사장님이 청소 인력에게 링크 보내기
4. 모두 새 링크로 열었는지 기록으로 확인한 뒤 → 워커 **잠금 켜기** (스위치 하나)

## 제약 및 주의사항
- ⚠ **이미 새어 나간 것은 못 거둔다.** 청소앱을 한 번이라도 연 휴대폰에는 에어비앤비 원주소가 저장돼 있다.
  완전히 막으려면 **에어비앤비 내보내기 주소를 새로 받아야** 한다. 에어비앤비에 재발급 기능이 있는지 공식 안내에서 못 찾음
  ([에어비앤비 도움말](https://www.airbnb.com/help/article/99)) → 사장님이 에어비앤비 화면·고객센터에서 확인 필요
- 기록은 "앱에서 누가 번호를 봤나" 까지다. 외운 번호로 문을 여는 것은 못 막는다 (도어락 출입 기록과 함께 볼 것)
- 링크를 남에게 넘기면 원래 주인 이름으로 기록된다 → 링크 보낼 때 "본인만 쓰기" 안내
- KV 쓰기 한도 원칙: 기록은 볼 때만 쓴다(앱 열 때마다 X). 10분 묶기·거절 하루 1줄
- #22·#26: `access_links` 는 예약앱 한 곳에서만 고치고 워커가 받는 즉시 전체를 다시 읽어 바꾼다 (통째 덮어쓰기 금지)
- #30: '오늘' 판정은 워커 `todayKST`
- 예약앱 캐시 10분 — 단계 2 뒤 강력 새로고침 필수

## 결정됨 (10/19)
1. 링크가 꺼지거나 없으면 **달력도 안 보임** — 그만둔 사람은 아무것도 못 본다
2. 청소앱 **호실 관리 화면 없앰** — 호실 추가·주소 수정·순서는 예약앱에서만
3. 청소 인력은 **당일 칸만** 비밀번호 입력·수정 가능, 전부 기록
4. 예약앱에 **청소 인력 명단** — 누가 쓰는지·마지막 접속·중지/다시 허용
5. 링크는 **처음 연 폰 한 대**에만. 다른 폰은 사장님 허용 후

6. **사장님 열쇠는 Cloudflare 보관 + 사본 1개 저장 둘 다** (사장님 결정 10/20) — 워커 비밀값 `OWNER_KEY`. 사장님 Cloudflare 계정으로만 바꿀 수 있다.
   ⚠ Cloudflare 비밀값은 **넣기만 되고 다시 꺼내 볼 수는 없다** → 잃어버리면 '새로 지정'이 복구 방법.
   평소 다시 열 링크 사본은 사장님만 로그인하는 곳(구글 드라이브·네이버 MYBOX·카톡 나와의 채팅 등)에 둔다

## 남은 확인 (구현과 별개)
7. 에어비앤비 내보내기 주소 새로 받기 — 사장님이 에어비앤비에서 확인 (구현과 별개로 진행 가능)
8. 기록 보관 기간 — **90일** (사장님 10/20). 하루 20회 열람 가정 시 3달 ≈ 1,800줄·0.3MB — 저장 부담 없음
