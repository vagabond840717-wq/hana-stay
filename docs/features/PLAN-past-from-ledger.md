### ⚠ 원장에 부킹닷컴이 한 건도 없다 — 이대로 1·2단계를 하면 진짜 부킹 손님이 지워진다
`ledger_2026-09`·`ledger_2026-10` 전체에 `bk` 조각 **0건**. 그런데 피드엔 부킹 숙박이 있었다:

```
601호 부킹 피드 (변화 기록)                원장 601호
  9/24        9/24~9/29                   9/24  빈 방
  9/25 00:00  → 9/25~9/29 (어젯밤 잘림)     9/25  빈 방
  9/26 00:00  → 9/26~9/29                  ...
  9/29 00:00  → 사라짐                     9/29  빈 방
```

- **부킹은 매일 한국시간 0시에 지난 밤을 잘라낸다** (5일 연속 00:00 정각 변화). 원장은 **다음날 07:30** 에 굳힌다
  → 굳힐 땐 그 밤이 이미 없다 → **부킹 숙박은 어떤 밤도 원장에 안 남는다.** 마지막 밤·퇴실 표시도 마찬가지
- 트립은 **이틀 뒤 01:00** 에 자른다(603호 9/28 01:00) → 07:30 굳히기로 잡힌다. 원장에 트립은 정상
- [DRAFT-past-ledger.md](DRAFT-past-ledger.md) 의 *"X 가 피드에 남는 시한 = X+2일 09:00"* 은 트립 실측이었고 **부킹엔 틀렸다**
- 그래서 아래 1단계의 *"진짜로 오늘 나가는 손님은 원장 어제 칸에 반드시 적혀 있다"* 는 **부킹 손님에겐 거짓**이다.
  그제 칸도 비어 있으니 받쳐주지 못한다 → **부킹 손님 퇴실날 청소 표시가 사라진다** (#29 재발)

### 그래서 순서를 하나 앞에 끼운다 — **선행 단계: 원장이 부킹 밤을 놓치지 않게**
- 5분 동기화 끝에서 **부킹 조각 중 '오늘 밤'을 덮는 것**을 작은 KV(`ledger_tonight`, 가칭·워커 전용)에 받아 둔다. **바뀔 때만 write**
- 다음날 07:30 굳힐 때 `buildDaySegs` 의 부킹 재료를 이 사진으로 대신한다 (입실일 상속·오늘 퇴실 이어붙이기 규칙은 그대로)
- 리브애니웨어도 같은 '재고형'이라 같이 취급 (예약 거의 없음)
- 왜 이 방식인가 — 대안 둘은 탈락:
  - 굳힐 때 수첩 '앞잘림 되돌리기'로 시작일 복원 → **마지막 밤을 못 살린다**(퇴실일 0시에 조각이 통째로 빠져 짝이 없음)
  - 전 채널을 그날 17:30 에 굳힘 → 저녁 당일 예약을 놓친다. 에어비앤비·트립은 지금 방식이 이미 정확
- 이 단계는 **화면 무변화.** 원장이 며칠 쌓인 걸 확인한 뒤 1단계로 간다
  (그동안 1단계의 '원장 어제·그제 칸이 둘 다 없으면 수첩으로' 폴백은 부킹엔 소용없다 — 원장에 다른 채널 칸은 있으므로.
  → 1단계 판정은 **채널별로** 폴백한다: 그 방 원장에 그 채널이 선행 단계 배포 이후로만 믿을 수 있음)

### 이미 굳은 원장의 부킹 빈칸 (9/21 ~ 선행 단계 배포일)

## 3. 바꾸는 것 (두 단계, 따로 배포)

### 1단계 — 워커: 오늘 퇴실 되살리기의 재료를 원장으로

**지금**: 수첩에서 `퇴실 == 오늘` 인 조각을 찾아 거름망 (가)(나) 통과 시 꺼낸다.
**바꿈**: 원장 **어제(T-1)·그제(T-2) 칸**에 `퇴실 == 오늘` 로 적힌 조각만 후보로 삼는다. 거름망 (가)(나)는 그대로.

- 진짜로 오늘 나가는 손님은 어젯밤 방에 있었다 → 원장 어제 칸에 반드시 적혀 있다
- 그제 칸도 보는 이유: 어제 칸은 오늘 07:30 에 굳는다. **새벽 0~7:30** 엔 아직 없다.
  또 부킹이 퇴실 당일 07:30 전에 목록에서 빼면 어제 칸에 못 들어갈 수 있다 → 그제 칸이 받쳐준다
- 꺼내는 모양도 원장 것을 쓴다 (입실일이 이미 바로잡혀 있다)
- **원장을 아예 못 읽으면**(그 방 어제·그제 칸이 둘 다 없음) 지금처럼 수첩으로 → **나빠지는 경우 없음**
  (오늘 퇴실 표시가 사라지면 청소를 놓치므로, 모르면 지금 동작 유지)
- 두 경로 모두 적용: `GET /bookings`(예약앱) · `GET /?url=&fix=tr|bk&room=`(청소앱, `fixIcalText` ③)
- 판정은 새 함수 `ledgerCheckoutCands(...)` 한 곳 (#2)

| 파일 | 변경 |
|---|---|
| `worker.js` | `readPrevDayLedger` 를 날짜 인자로 일반화(`readLedgerDay`) · `ledgerCheckoutCands` 신설 · `applyUntrim` ②와 `fixIcalText` ③의 후보 목록만 교체 |

**효과**: 501호 10/2 — 원장 10/1·9/30 칸에 9/28~10/2 없음 → 안 꺼냄 → `✈인` 만 남는다.

### 2단계 — 워커 + 예약앱: 지난 날짜를 원장으로

**지금**: 예약앱이 `/archive`(수첩)를 받아 `퇴실 < 오늘` 을 전부 그린다 (메아리만 거름).
**바꿈**: 워커가 **화면용 지난 목록** `GET /past` 를 만들어 주고, 앱은 수첩 대신 이걸 그린다.

`/past` 만드는 규칙 (호실·채널별):
- 그 방 원장 첫날을 `L` 이라 하면
  - **퇴실 ≤ L** → 수첩 그대로 (원장 이전 시대. 지금과 같음)
  - **퇴실 > L** → **원장에서만**. 수첩 것은 안 쓴다
- 원장 → 조각: 원장 모든 날의 조각을 **입실일로 묶어** 가장 늦은 날의 모양을 쓴다
  (입실일은 원장이 이어받아 고정해 두므로 같은 손님 = 같은 입실일. 연장·단축이면 마지막 모양이 이긴다)
- 그 방 원장이 아예 없으면 → 수첩 그대로 (새 호실 등)
- 모양은 수첩과 같은 `{cinY,cinM,cinD,coutY,coutM,coutD,summary}` — 앱 쪽 코드가 그대로 먹는다

예약앱:
- `loadArchive()` 옆에 `loadPast()` — `/past` 를 `pastData` 로
- `mergeArchiveIntoRooms()` 의 재료만 `archiveData` → `pastData` (못 받으면 `archiveData` 로 — 지금과 같음)
- 메아리 거름·앞잘림 정리·경계 적용 등 **나머지 로직은 그대로**
- **통계(`calcOccupancy` 등)는 그대로 수첩** — 이번 범위 밖 (월별 결산 때 별건)

| 파일 | 변경 |
|---|---|
| `worker.js` | `buildPastSegs` 신설 · 라우트 `GET /past` |
| `booking/index.html` | `pastData`·`loadPast()` 추가 · `init`/`triggerSync` 에서 같이 받기 · `mergeArchiveIntoRooms` 재료 교체 |

**효과**: 501호 `9/28~10/2` 는 퇴실이 `L`(9/21) 이후라 원장에서만 찾는다 → 없음 → 안 그려짐.
앞으로 원장 시대의 지난 화면에는 **피드에 실제로 있던 것만** 나온다.

**안 고쳐지는 것**: 원장 이전(퇴실 ≤ 9/21) 유령은 그대로 — 401호 `9/3~9/18` 등. 원장이 없으니 가릴 근거가 없다.
