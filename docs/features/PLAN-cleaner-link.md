## 큰 그림 — '잠금 스위치'를 맨 마지막에 켠다
워커에 **잠금 스위치**(KV `access_enforce`)를 둔다. 꺼져 있는 동안은
**열쇠 없는 요청이 지금과 바이트 단위로 똑같이** 동작하고, 열쇠가 붙은 요청만 새 규칙(기록·기기 묶기)을 탄다.
→ 워커·예약앱·청소앱을 하나씩 배포해도 아무도 안 잠긴다. 모두 새 링크로 바꾼 걸 명단에서 확인한 뒤 사장님이 켠다.
문제가 생기면 **스위치만 끄면 즉시 원래대로** (재배포 불필요).

## 작업 단위 (순서대로)

### Task 1: 워커 — 열쇠 확인의 뼈대
- 파일: `ical-proxy/worker.js`
- 변경 내용:
  - 요청 머리글 `X-Hana-Key`(열쇠) · `X-Hana-Dev`(기기 번호)를 읽어 **누구인지** 판정하는 `whoIs(env, request)`
    → `{role:'owner'}` / `{role:'clean', link, ok}` / `{role:'clean', state:'pending'|'stopped'}` / `{role:'none'}`
  - 열쇠·기기 번호는 SHA-256 해시로만 비교·저장
  - 사장님 열쇠 = KV `access_owner`(해시) **또는** 워커 비밀값 `OWNER_KEY` (Cloudflare 설정 화면 — 복구용)
  - 청소 열쇠: KV `access_links` 에서 찾기. 처음 쓰는 기기면 그 기기에 묶음 / 다른 기기면 `pending` 에 올리고 거절
  - `lastUsed` 는 하루 1번만 갱신 (KV 쓰기 한도)
  - CORS `Access-Control-Allow-Headers` 에 `X-Hana-Key, X-Hana-Dev` 추가 + `Access-Control-Max-Age: 86400` (사전 확인 요청 줄이기)
  - `access_links` 는 요청마다 읽는다 (isolate 메모리에 30초 캐시)
- 예상 코드: ~90줄

### Task 2: 워커 — 기록 + 링크 관리 길
- 파일: `ical-proxy/worker.js`
- 변경 내용:
  - `logAccess(env, rows)` → KV `access_log` (최신이 앞, 5,000줄·90일). 같은 사람·같은 서랍 `view` 는 10분 안이면 한 줄로
  - `GET /access/me` — 앱이 '나는 누구·상태'를 묻는 길 (`{role, name, state, enforce}`)
  - `POST /access/owner/claim` — **사장님 열쇠가 아직 없을 때 딱 한 번** 워커가 무작위 열쇠를 만들어 돌려줌(해시만 저장).
    이미 있으면 거절. (Claude 도 열쇠를 모르게 하려는 장치. 빼앗기면 `OWNER_KEY` 로 복구)
  - `GET /access/links` · `POST /access/links` (사장님만) — `add`(이름 → 새 열쇠 1회 반환) · `stop` · `resume` ·
    `approve`/`reject`(새 기기) · `renew`(새 열쇠 발급, 옛 링크·기기 끊김) · `enforce`(잠금 켜기/끄기)
    - 공유 배열 → 받는 즉시 KV 를 다시 읽고 그 한 사람만 고쳐 쓴다 (#22·#26). 못 읽으면 쓰지 않음
  - `GET /access/log?name=&limit=` (사장님만)
- 예상 코드: ~110줄

### Task 3: 워커 — 비밀번호가 나가는 길마다 검사
- 파일: `ical-proxy/worker.js`
- 변경 내용 (규칙표는 스펙 '워커에서 바뀌는 길'):
  - `todayDrawerRole(env, key)` — 서랍 키(`호실|입실일[_꼬리]`)가 **오늘 체크인(in)·체크아웃(out)** 인지.
    재료는 `/bookings` 와 같은 교정본(`applyDaylock`+`applyUntrim`) — ⚠ 부킹·트립은 자정에 오늘 퇴실분을 잘라내므로
    원본(`synced_bookings`)만 보면 오늘 퇴실 서랍을 못 찾는다. 수동 블락(`_bl`)은 `manual_blocks` 로
  - `GET /extra?key=<서랍>`: 청소 열쇠 + 오늘 서랍 → 비밀번호 + `auto`(에어비앤비 `ph`) + `open:true` → `view` 기록.
    그 밖 → `passwords:[]`, `open:false`. 사장님 → 그대로
  - `POST /extra` (서랍): 비밀번호를 볼 수 없는 요청이면 **서버의 비밀번호를 그대로 두고 메모만 반영**.
    청소 열쇠 + 오늘 서랍 → 반영하고 바뀐 번호를 `set`/`del` 기록
  - `GET /rooms`: 청소 열쇠 → 원주소 4개 빈칸. `POST /rooms`: 청소 열쇠는 **항상 거절**
  - `GET /feed?room=&ch=ab|bk|tr|lv` (새): 저장된 주소로 받아 `bk`·`tr` 는 기존 `fixIcalText`, `ab` 는 **설명 줄 전부 삭제**, `lv` 그대로
  - `GET /bookings`: 잠금 켜짐 + 사장님 아님 → `ph` 뺌
  - **잠금 켜짐**일 때만: 열쇠 없음·중지·대기 → 위 길들과 공유 목록(`/extra?key=manual_blocks` 등) **전부 403** + `deny` 기록(같은 열쇠 하루 1줄)
  - ⛔ `/ical/…` 내보내기 · `/sync` · cron · `/push/*` · 진단 길은 건드리지 않는다
- 예상 코드: ~120줄

### Task 4: 예약앱 — 사장님 열쇠 + 청소 인력 명단 + 열람 기록
- 파일: 예약앱 `index.html`
- 변경 내용:
  - 맨 앞에 워커 요청 감싸개: `PROXY` 로 가는 `fetch` 에 `X-Hana-Key` 를 자동으로 붙인다 (23군데를 하나씩 안 고침)
  - 주소의 `#k=` 를 읽어 `hana_owner_key` 에 저장하고 주소창에서 지움
  - ☰ 패널에 `👥 청소 인력` 버튼 → 새 패널:
    - 사장님 열쇠가 없으면: `사장님 열쇠 만들기` → 링크 표시 + `복사` · `공유` + "구글 드라이브나 카톡 나와의 채팅에 저장하세요"
    - **명단**: 이름 · 상태 배지(`일하는 중`/`새 폰 확인 필요`/`중지됨`) · 마지막 접속 · 폰 기종 · 이번 달 열람 수 ·
      `중지`/`다시 허용` · `허용`/`거절` · `새 링크`
    - `새 사람 추가` → 이름 → 링크 + `카톡으로 보내기`(`navigator.share` → 휴대폰 공유창, 안 되면 복사) + 안내문
      ("이 링크는 본인 폰 한 대에서만 열려요. 카톡에서 열렸다면 오른쪽 위 메뉴 → 다른 브라우저로 열기 → 홈 화면에 추가")
    - **열람 기록**: 시각 · 이름 · 방 · 나가는/들어오는 손님 · 봄/바꿈/지움/거절. 이름으로 거르기
    - **잠금 스위치**: 꺼짐/켜짐 + 켜기 전 확인창("새 링크로 안 연 사람은 청소앱을 못 써요")
- 예상 코드: ~200줄

### Task 5: 청소앱 — 링크로만 열리기
- 파일: 청소앱 `index.html`
- 변경 내용:
  - 워커 요청 감싸개 (`X-Hana-Key` + `X-Hana-Dev`). 기기 번호는 처음 열 때 무작위로 만들어 `hana_dev` 에 저장
  - `#k=` 읽어 `hana_key` 저장 · 주소창 정리
  - 시작할 때 `GET /access/me` → 상태가 `ok` 가 아니고 잠금이 켜져 있으면 **안내 화면만**:
    없음 "사장님께 받은 전용 링크로 열어주세요" / 대기 "사장님 확인을 기다리는 중이에요" / 중지 "사용이 중지됐어요"
  - 맨 위에 작게 이름 표시
  - 피드를 `/feed?room=&ch=` 로 받기 (원주소 안 씀). `parseIcal` 등 파서 4개는 그대로
  - **호실 관리 제거**: ☰ 버튼·호실 관리 패널·`saveRooms` 호출 전부 (색 마이그레이션 자동 저장 포함 — 원주소 빈칸으로 덮어쓰면 큰일)
  - 비밀번호를 휴대폰에 남기지 않기: 서랍은 메모리에만. 시작할 때 옛 `hana_ex_*` 전부 지우고 `hana_rooms` 에서 원주소 제거
  - 비밀번호 상자: 서버가 `open:false` 면 `🔒 당일 공개` (화면 규칙 `pwOpenToday` 는 보조로 유지). `auto` 가 있으면 자동 번호 표시
- 예상 코드: ~120줄

## 롤백 방법
- **1순위: 잠금 스위치 끄기** (예약앱 버튼 또는 KV `access_enforce` 삭제) → 즉시 지금처럼 동작
- 2순위: 저장소마다 위 커밋으로 `git revert` → 푸시
- 새 KV 3개(`access_owner`·`access_links`·`access_log`)는 남아도 무해. 서랍·호실 데이터는 모양을 안 바꾼다
- ⚠ 청소앱을 되돌려도 호실 관리를 다시 쓰면 안 된다 — 잠금 켜진 상태에서 옛 청소앱은 원주소 없이 저장할 수 있으므로
  워커의 `POST /rooms` 청소 열쇠 거절은 되돌리지 않는다

## 예상 주의사항
- **#22·#26** `access_links` 공유 배열 — 워커가 다시 읽고 한 사람만 고친다. 못 읽음 ≠ 비어 있음
- **#30** 오늘 판정은 워커 `todayKST`. 청소앱 화면 보조 규칙만 기기 날짜
- **KV 쓰기 한도** — 기록은 볼 때·바꿀 때만, 10분 묶기, 거절 하루 1줄, `lastUsed` 하루 1번
- **POST /extra 보존** — 이게 빠지면 빈칸으로 받은 앱이 메모 저장할 때 비밀번호가 지워진다. 시험 필수
- 예약앱 캐시 10분 — 단계 2 뒤 강력 새로고침
- 청소앱은 카톡 안 브라우저로 처음 열릴 가능성이 높다 → 나중에 크롬으로 열면 '새 폰' 이 된다. 안내문 + 사장님 허용으로 처리
- `render()` → `attachCellClicks()` 체인은 안 건드린다 (청소앱 안내 화면은 `render` 전에 끊는다)
- 이미 새어 나간 에어비앤비 원주소는 이 작업으로 못 거둔다 → 사장님이 에어비앤비에서 새 주소 발급 가능한지 확인 (스펙 7번)
