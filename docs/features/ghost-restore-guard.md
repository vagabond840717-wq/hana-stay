## 요약
아카이브에서 지난 예약을 꺼내 화면을 메울 때 **"꺼낼 필요가 있는가"** 를 먼저 따진다.
이미 있는 예약과 겹치거나, 원 예약의 메아리인 조각은 주입하지 않는다.

**두 곳에서 막는다** — 워커가 '오늘 퇴실'분을, 예약앱이 '지난 날짜'분을 맡는다.

### 원인 둘

**① 워커 — 날짜 완전일치로만 중복을 걸렀다**
`restoreTodayCheckouts` 가 "퇴실 == 오늘"인 아카이브 조각을 꺼낼 때,
입실·퇴실이 **토씨까지 같은** 조각만 "이미 있다"로 쳤다.
예약이 하루라도 줄면 남남 취급 → 옛 버전이 나란히 주입됐다.
그 뒤 앱의 **포함 관계 정리**(index.html:2083)가 **넓은 쪽(가짜)을 남기고 진짜를 지웠다.**

**② 예약앱 — 지난 날짜를 꺼낼 때 메아리를 안 걸렀다**
`mergeArchiveIntoRooms` 는 "퇴실 < 오늘"인 조각을 전부 꺼낸다.
부킹·트립 차단 중 상당수가 **우리 예약이 그 채널로 건너갔다 돌아온 메아리**인데 구분이 없었다.

## 기능 상세

### 사용자 시나리오
손님이 어제 나갔다. 아침에 달력을 연다.
→ (전) 방이 아직 차 있고 오늘 퇴실로 보인다. 어제 칸엔 퇴실 도장이 세 개다.
→ (후) 방은 비어 있고, 어제 칸에 퇴실 도장이 하나다.

### UI/UX
**화면 구성 변경 없음.** 잘못 그려지던 칸이 바르게 그려질 뿐이다.

### 동작 규칙

#### 워커 — 오늘 퇴실분 (`shouldRestoreSeg`)
기존 조건 유지: `퇴실 == 오늘` · `입실 < 오늘`(당일치기·꼬리 제외)

**(가) 그 방 어느 채널이든 겹치는 조각이 피드에 있으면 안 꺼낸다**
- 한 방에 한 팀이다. 채널이 달라도 같은 밤을 두 팀이 쓸 수 없다
- 겹친다면 독립된 진짜 예약이 아니라 **같은 숙박의 옛 버전이거나 채널 간 메아리**다. 피드 쪽이 최신이다
- 이 검사가 옛 '날짜 완전일치'를 **대체한다** (같은 조각도 겹치므로)
- ⚠ **'같은 채널'로 좁히면 603호를 놓친다.** 처음 그렇게 짰다가 실데이터에서 걸렸다

**(나) 그 방에 '오늘 퇴실'이 이미 표시돼 있으면 안 꺼낸다 (채널 무관)**
- 규칙의 목적이 '퇴실 표시가 사라지는 것' 방지다. 이미 보이면 꺼낼 이유가 없다

판정 재료 `roomSegs` 는 **네 채널을 가로질러 누적된다** — 되살린 조각끼리도 겹치지 않는다.

#### 예약앱 — 지난 날짜분 (`mergeArchiveIntoRooms`)
**부킹·트립·리브 차단의 퇴실일이 같은 방 에어비앤비 예약의 퇴실일과 같으면 메아리다 → 안 꺼낸다.**

- 근거: 메아리는 우리가 예약을 그 채널로 내보내서 생긴다. 채널이 **우리 퇴실일까지** 막으므로
  **끝 날짜가 반드시 일치한다.** 시작은 채널이 이웃 블록과 뭉쳐 달라진다
- 안전: 한 방에 한 팀 → 두 채널이 같은 날 퇴실할 수 없다 → 진짜를 지울 일이 없다
- ⚠ **'겹치기만 하면 제외'로 넓히지 말 것.** 트립은 이웃 블록을 뭉쳐 보내므로
  진짜 트립 손님이 낀 덩어리까지 통째로 사라진다 (402호 `tr 7/9~7/24` 등 실측)

## 기술 구현 방안 (채택안)

**판정을 한 곳에 모은다.** 워커의 두 읽기 경로가 `shouldRestoreSeg` 하나만 쓴다 (#2 대비).

```js
function shouldRestoreSeg(as, az, roomSegs, todayMs, checkoutShown) {
  if (az !== todayMs || as >= todayMs) return false;   // 기존 조건
  if (checkoutShown) return false;                     // (나)
  return !(roomSegs || []).some(([s, e]) => as < e && s < az);   // (가)
}
```

**검토했으나 버린 안**
- *주입 후 사후 정리* — 앱의 포함 관계 정리가 **넓은 쪽을 남기므로** 진짜가 지워지는 걸 못 막는다
- *포함 관계 정리를 '좁은 쪽 남기기'로 변경* — 워커·예약앱·청소앱 세 곳을 동시 수정해야 하고,
  정상적인 아카이브 중복 정리까지 망가진다. 근본 원인(가짜 주입)도 그대로 남는다

## 제약 및 주의사항

- **#29 의 목적은 유지된다.** 진짜로 사라진 퇴실은 여전히 되살아난다. 이미 보일 때만 안 꺼낸다
- **#16 원칙 유지** — 앞날 것은 절대 안 꺼낸다
- **한계: 진짜 예약이 피드에서 이미 사라진 뒤라면 겹칠 상대가 없어 유령을 못 막는다**
  (401호 `9/3~9/18` 15박, #31). 그건 past-ledger 가 맡는다
- **past-ledger ⑦ 과 겹친다.** 원장 전환 시 이 판정들은 함께 제거 대상이다.
  원장은 2026-09-19 부터 쌓기 시작해 아직 얕다 — 그때까지 대기분 63건을 막는 임시 조치다
- ⚠ **예약앱은 PWA다.** 배포해도 브라우저가 옛 버전을 붙들고 있어, **캐시를 비워야 반영된다.**
  이번에도 여기서 한 번 어긋났다 — `?v=` 를 붙여 받으면 새 코드가 보이는 게 당연하므로
  그것만으로 "반영됐다"고 판단하면 안 된다
