# 트립·부킹 예약 합쳐짐 알림 (trip-merge-alert) 스펙

> 상태: **초안 — 사장님 승인 대기** (2026-11-04)
> 세션: `11/04 트립 예약 합쳐짐`

## 요약
트립닷컴·**부킹닷컴** 예약 덩어리가 **옆 날짜와 이어져 한 덩어리로 커지는 순간**, 폰 푸시 + 🔔 카드 + 달력 ⚠ 로 알리고
`두 팀이에요`(그 날짜에 경계 넣기) / `한 팀(연장)이에요`(그대로 두기) 버튼으로 확인받는다.

## 목적 및 배경
- 트립·부킹 iCal 은 예약이 아니라 '못 파는 날'을 보낸다 (#29). 날짜가 이어진 두 예약은 **한 덩어리 VEVENT 로 합쳐져** 온다 (#25·#28).
- 그래서 601호처럼 `11/5~11/8` 이 먼저 들어와 있다가 뒤에 새 예약이 붙으면, 피드는 `11/5~11/12` 같은 통짜 하나만 보낸다.
  화면에서 11/8 교대(아웃+인)가 사라지고 → **청소 일정에서 그날 교대 청소가 빠진다.**
- 지금 앱의 ⚠ 는 **이미 경계를 넣어둔 날짜**가 새 통짜에 삼켜질 때만 뜬다 (`detectCutAlerts`). 경계가 없던 곳에서 처음 붙으면 **아무 말이 없다.**
- 피드만으로는 '새 손님이 붙음' 과 '같은 손님이 연장' 을 구분할 수 없다 (트립은 예약 번호를 안 준다. 리서치·split-inherit 때도 같은 결론).
  → 붙은 순간을 놓치지 않고 **사람에게 한 번 묻는 것**이 유일하게 안전한 방법.

## 기능 상세

### 사용자 시나리오
**A. 뒤에 붙음 (가장 흔함)** — 601호 트립 `11/5~11/8` 이 있는데 `11/8~11/12` 예약이 들어옴
1. 5분 안에 워커가 피드 `11/5~11/12` 를 받고, 직전 모양과 비교해 **11/8 이음매**를 찾는다
2. 폰 푸시: `🔗 601 jnj 트립 예약 합쳐짐` / `11/8 에서 이어져 11/5~11/12 한 덩어리 — 두 팀인지 확인해 주세요`
3. 🔔 맨 위에 카드 + 달력 601호 11/8 칸에 ⚠
4. 사장님이 트립 앱에서 확인 후
   - `두 팀이에요` → 11/8 에 경계 저장 → 달력이 `11/5~11/8 | 11/8~11/12` 로 나뉨(아웃/인). 청소앱에도 반영
   - `한 팀(연장)이에요` → 그대로 두고 확인 처리
5. 어느 쪽이든 ⚠·카드가 사라지고 다시 묻지 않는다

**B. 앞에 붙음** — `11/8~11/12` 앞에 `11/5~11/8` 이 들어옴 → 이음매 11/8, 같은 흐름

**C. 사이가 메워짐** — `11/5~11/8` 과 `11/10~11/12` 사이에 `11/8~11/10` 이 들어옴 → 이음매 **11/8, 11/10 두 개**. 카드 하나에 두 날짜, 버튼은 날짜별

**D. 동시에 들어온 경우** — 붙은 모양으로 처음부터 들어오면 직전 모양이 없어 **못 잡는다.** (한계 — 아래)

**F. 부킹 (사장님 결정 11/04: 부킹도 한다)** — 같은 흐름. `두 팀이에요` 를 누르면 **부킹 경계**가 저장된다
(지금 경계는 트립 전용 → 이번에 부킹까지 넓힌다. 아래 '영향 받는 파일')

**E. 붙었다가 풀림** — 트립 '문의' 날짜가 잠깐 붙었다가 거절로 빠짐(#25) → 이음매가 더는 덩어리 한가운데가 아니면
카드는 자동으로 `풀렸어요` 확인 처리(푸시 없음), ⚠ 사라짐

### 알리지 않는 경우 (소음 방지)
| 경우 | 이유 |
|---|---|
| 이음매 날짜가 **오늘 이전** | 지난 일 — 청소 일정에 영향 없음 |
| 그 날짜에 **이미 경계가 있음** | 이미 나눠 둠 |
| **저녁 6시 가짜 만실**(#28·#39) | 워커의 당일잠금 판정을 먼저 적용한 모양끼리 비교. 판정이 놓쳐도 '붙은 게 오늘 밤 1박뿐 + 18시~자정'이면 안 알림 |
| **부킹 판매 기간 끝 롤링** — 몇 달 뒤 '안 파는 기간' 덩어리가 매일 하루씩 움직임 | 길이 **90박 넘는 부킹 덩어리**의 이음매는 안 알림 (601호 7개월짜리 등). 배포 전 변화 기록 재생으로 기준 확정 |
| **앞잘림** (시작일만 늦어짐) | 덩어리가 커진 게 아니라 줄어든 것 |
| **피드가 통째로 빔**(트립 하루 수회 5~15분) | 빈 피드로는 '직전 모양'을 덮어쓰지 않는다. 돌아왔을 때 끊기기 전 모양과 비교 → 끊긴 사이에 붙은 것도 잡음 |
| 같은 방·같은 이음매를 **이미 물어봄** | 한 번만 묻는다 (그 날짜가 지날 때까지 기억) |

### UI/UX
- **푸시**: 기존 PWA 푸시 그대로 (`sendPushToAll`). 누르면 앱이 열림
- **🔔 카드** (서버 알림 목록 맨 위, 미확인이면 주황 테두리)
  ```
  🔗 601 jnj · 트립 예약 합쳐짐
  11/8 에서 이어져 11/5 ~ 11/12 한 덩어리가 됐어요
  트립 앱에서 손님이 바뀌는지 확인해 주세요
  [ 두 팀이에요 — 11/8 나누기 ]  [ 한 팀(연장)이에요 ]
  11/4 15:52
  ```
- **달력 ⚠**: 미확인 동안 이음매 칸에 기존 ⚠ 배지(경계 확인과 같은 모양). 칸을 눌러 상세 창에서도 같은 두 버튼
- 🔔 숫자에 포함. 기존 '📅 새 예약' 알림은 **그대로 둔다** (사장님 결정 11/04)
  — 그래서 붙음 때 '📅 새 예약 11/5~11/12' 도 같이 올 수 있다

## 기술 구현 방안
- 옵션 A: 예약앱이 열릴 때 판정 (지금 `detectCutAlerts` 처럼) — 앱을 열기 전엔 모름. **푸시 불가.** ✗
- 옵션 B: **워커 5분 동기화에서 판정 → 알림 목록(events)에 `merge` 로 저장 + 푸시.** 앱은 보여주고 버튼만 처리 ✔
- **권장: B.** 판정은 워커 한 곳에만 둔다(#2). 앱을 안 열어도 붙는 순간 폰에 온다.

### 판정 규칙 (워커)
```
대상: 트립(tr)·부킹(bk). 채널별로 따로 비교 (트립은 당일잠금 적용본끼리).
직전 모양 P목록 (기억표) vs 지금 모양 N목록
지금 덩어리 N 마다, N 과 겹치거나 맞닿는 직전 조각 P 에 대해:
   P.퇴실 < N.퇴실  →  이음매 = P.퇴실   (뒤에 붙음)
   P.입실 > N.입실  →  이음매 = P.입실   (앞에 붙음)
이음매가 N 의 한가운데(N.입실 < 이음매 < N.퇴실)이고 ≥ 오늘이고,
그 채널 경계(tr_cuts)가 없고, (부킹) N 이 90박 이하이고, 이미 물어본 적 없으면 → 알림
```

  - 경계를 부킹까지: `SPLIT_PLATFORMS = ['tr','bk']` · 상세 창의 경계 넣기/지우기(지금 트립 칸 전용)를 부킹 칸에도
    — 잘못 누른 `두 팀` 을 되돌릴 길이 있어야 한다

- 청소앱(`jnjhana`): `SPLIT_PLATFORMS = ['tr','bk']` 한 줄 — 부킹 경계로 나눠 그리기 (기준 앱=예약앱에 맞춤)

## 데이터 변경
- 새 KV `tr_merge_watch` (워커 전용, `extra_` 없음): `{ rooms:{ "601 jnj":{ tr:[{cin:"20261105",cout:"20261108"}], bk:[...] } }, asked:{ "601 jnj|tr|20261108": ts } }`
- 알림 이벤트 새 종류: `{ type:'merge', room, ch:'tr'|'bk', platform:'Trip.com'|'Booking.com', joint:"2026/11/08", cin, cout, ts, read }`

## 제약 및 주의사항
- **한계 1 — 동시에 들어오면 못 잡는다** (직전 모양이 없음). 배포 첫 회도 마찬가지: 지금 이미 붙어 있는 덩어리는 알리지 않는다
- **한계 2 — 같은 손님 연장도 똑같이 알린다.** 구분 불가라 버튼으로 묻는다
- 기존 ⚠ (`detectCutAlerts`, 넣어 둔 경계가 삼켜짐) 는 그대로 둔다 — 서로 다른 경우
- KV write: 트립 모양이 바뀔 때만 (하루 수십 번 수준, 한도 영향 미미)
- #28·#39 당일잠금과 순서: 반드시 `updateDaylock` 뒤에 판정
- 예약앱 배포 후 GitHub Pages 캐시 10분 → 강력 새로고침 안내

- **배포 전 필수 검증 — 변화 기록 재생**: `/changes` (9/22~) 트립·부킹 변화를 새 규칙으로 돌려 '몇 번 울렸을지' 전수 확인.
  부킹 롤링·트립 문의 깜빡임이 알림 폭탄이 되지 않는지 여기서 잡는다. **워커 주소 접속이 필요** (이 클라우드 세션은 막혀 있음)
- 부킹 경계를 넣어도 **내보내기(`exportIcal`)는 무영향** — 경계는 표시만 나눈다. 배포 시 45주소 바이트 대조
