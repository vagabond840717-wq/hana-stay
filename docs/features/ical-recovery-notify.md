# iCal 연결 오류 알림 자동 복구 처리 스펙

## 요약
iCal 연결 오류 알림이 떠 있는 상태에서 연결이 다시 성공하면, 오류 알림을 자동으로 "확인됨" 처리하고 "✅ 다시 연결됨" 알림을 새로 남겨 사용자가 복구 여부를 즉시 알 수 있게 한다.

## 목적 및 배경
현재 동작: Worker가 5분마다 동기화하면서 같은 호실·플랫폼이 3회 연속 실패하면 "⚠️ 연결 오류 (15분 이상 실패)" 푸시+알림을 남긴다. 그런데 **연결이 복구되면 내부 실패 카운터만 조용히 지우고 끝**이라, 알림 내역에는 오류가 미확인 상태로 계속 남는다. 사용자는 지금 정상인지 아닌지 알 수 없다.

모니터링 도구(Datadog, Grafana 등)의 표준 패턴도 "장애 알림은 복구 시 auto-resolve + recovery 알림 발송"이다.

## 기능 상세

### 사용자 시나리오
1. 밤사이 Booking.com iCal이 끊겨 "⚠️ 501 hana 연결 오류" 알림이 옴.
2. 아침에 연결이 저절로 복구됨.
3. (변경 후) 알림 내역을 열면:
   - 기존 오류 알림은 자동으로 **확인됨(흐림 처리)** 상태
   - 바로 위에 **"✅ 501 hana 다시 연결됨 — Booking.com iCal 연결이 복구됐어요"** 알림이 새로 떠 있음
4. 미확인 배지 수도 오류 알림만큼 줄어 있음.

### 동작 규칙
- Worker의 5분 주기 동기화(cron)에서 호실·플랫폼별 iCal fetch가 **성공**할 때마다:
  1. 알림 이벤트 목록에서 **같은 호실 + 같은 플랫폼의 미확인(`read:false`) `error` 이벤트**를 찾는다.
  2. 있으면 → 전부 `read:true`로 자동 확인 처리.
  3. 동시에 `type:'recovered'` 이벤트를 새로 저장하고 푸시 알림 발송("✅ {호실} 다시 연결됨").
  4. 없으면 → 아무것도 하지 않음 (평소 정상 동기화에서는 부담 0).
- 실패 카운터가 1~2회에서 복구된 경우(오류 알림이 발송된 적 없음) → 복구 알림도 없음 (알림 스팸 방지).
- 앱(알림 패널)에서는 `recovered` 타입을 ✅ 아이콘 + 초록 계열로 렌더링.

### UI/UX
- 알림 카드: `✅ 501 hana` / `Booking.com iCal 연결이 복구됐어요` / 시각
- 색상: 아이콘·제목 `#166534`(진초록), 미확인 배경 `#f0fdf4`(연초록)
- 복구 알림 자체는 일반 알림처럼 [확인] 버튼으로 수동 확인 (자동 확인되는 건 **오류 알림 쪽만**).

## 기술 구현

### 옵션 B — 미확인 오류 이벤트 기반 (채택)
성공 시 이벤트 목록에서 해당 호실·플랫폼의 미확인 `error` 이벤트 존재 여부로 판단.
- 배포 직후 이미 남아 있는 미확인 오류 알림도 다음 동기화 때 자동 정리 (자가 치유).
- events KV는 `syncAllRooms` 시작 시 1회 로드 후 감지용으로 사용, 복구 처리는 루프 완료 후 일괄 적용.

### 플래핑 대비
오류 알림 자체가 "3회 연속 실패(15분)"를 요구하므로 오류→복구 반복은 최소 15분 주기로 제한됨.

## 영향 받는 파일
| 파일 | 변경 내용 |
|------|----------|
| `ical-proxy/worker.js` | `syncAllRooms()` 성공 분기에 복구 감지·자동 확인·`recovered` 이벤트 저장·푸시 발송 추가 |
| `app/JnJ booking/index.html` | `renderNotifyEvents()`에 `recovered` 타입 아이콘/색상/문구 렌더링 추가 |

- 청소 앱(JnJ)은 알림 기능이 없으므로 수정 불필요.
- 달력/예약 표시/블락 로직 영향 없음.

- 기존 데이터 구조·bkKey·Room 객체 변경 없음.
