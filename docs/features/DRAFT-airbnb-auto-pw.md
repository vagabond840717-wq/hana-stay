# 에어비앤비 비번 자동 스펙

## 요약
에어비앤비 예약은 손님 전화번호 끝 4자리를 도어락 비밀번호로 예약앱에 저절로 띄운다. 따로 입력하지 않는다.

## 목적 및 배경
- 에어비앤비 달력 피드는 예약마다 손님 전화번호 끝 4자리를 함께 보낸다
  (`DESCRIPTION: … Phone Number (Last 4 Digits): ####`).
- 사장님은 에어비앤비 손님 비밀번호를 이 4자리로 쓰기로 했다 (10/16 모바일 대화).
- 지금은 예약마다 손으로 입력해야 한다. 실제로는 아무도 입력하지 않고 있다
  (10/16 실측: 지금 피드에 있는 에어비앤비 예약 24건 **전부 비밀번호 비어 있음**).

### 실측 (2026-10-16, 9개 호실 원본 피드)
| 항목 | 결과 |
|---|---|
| 에어비앤비 예약(`Reserved`) | 24건 |
| 끝 4자리가 들어 있는 예약 | **24건 (100%)**, 전부 숫자 4개 |
| 이미 손으로 넣은 비밀번호 | 0건 → 겹칠 일 없음 |

## 기능 상세

### 사용자 시나리오
- 사장님이 예약앱에서 에어비앤비 예약 칸을 누른다
  → **🔑 도어락 비밀번호** 칸에 `1371` 같은 번호가 이미 떠 있다. 밑에 작게 `✈ 전화번호 끝 4자리 (자동)`.
- 손님이 다른 번호를 원해서 바꿔야 한다 → 지금처럼 `수정`으로 입력한다 → **입력한 번호가 이긴다.**
  자동 번호는 사라지지 않고 그 아래 참고로 남는다.
- 손님이 날짜를 바꾼다 → 같은 예약이니 번호도 그대로 따라간다.
- 예약이 취소된다 → 피드에서 빠지므로 번호도 같이 사라진다.

### 화면 (예약앱 상세 창만)
```
🔑 도어락 비밀번호
┌────────────────────────────┐
│  1371              [수정]  │
│  ✈ 전화번호 끝 4자리 (자동)  │
└────────────────────────────┘
```
- 자동 번호에는 `삭제` 버튼이 없다 (저장한 게 아니라 피드에서 읽어 보여주는 것이라서).
- 손으로 넣은 번호가 있으면 지금 화면 그대로 + 맨 아래 `✈ 전화번호 끝 4자리: 1371` 한 줄.

### 동작 규칙
1. **에어비앤비 예약만.** 부킹·트립·리브는 피드에 전화번호가 없다.
2. **손으로 넣은 번호가 항상 먼저.** 자동 번호는 입력이 없을 때만 큰 글씨로 보인다.
3. 아무것도 저장하지 않는다. 보여주기만 한다.

## 기술 구현 방안

### 옵션 A — 보여주기만 (권장)
워커가 에어비앤비 피드를 읽을 때 끝 4자리도 뽑아 예약에 붙여 둔다 → 예약앱이 받는 예약 목록에 같이 실린다
→ 예약앱은 손으로 넣은 비번이 없으면 그걸 보여준다.
- 👍 저장 공간에 아무것도 안 쓴다 → 기존 비번·메모 서랍과 절대 안 부딪친다
- 👍 날짜 변경·취소를 저절로 따라간다 (피드가 진실)
- 👎 예약이 피드에서 빠지면(에어비앤비는 퇴실+2일) 자동 번호도 안 보인다 → 지난 예약은 안 보임. 실사용엔 무관

### 옵션 B — 서랍에 저장
워커가 새 에어비앤비 예약을 볼 때마다 그 예약의 비밀번호 서랍에 4자리를 써 넣는다.
- 👍 청소앱도 고치지 않고 바로 보인다 (같은 서랍을 읽으므로)
- 👎 날짜가 바뀌면 서랍 이름(입실일)이 바뀐다 → 메모처럼 옮기는 장치가 또 필요
- 👎 사장님이 지운 번호를 다음 동기화가 다시 써 넣는 문제가 생긴다
- 👎 저장 쓰기가 늘어난다 (KV 한도 원칙)

### 권장: 옵션 A
요청이 "예약앱에서 보이게"이고, 저장을 안 하니 기존 기능을 망가뜨릴 길이 가장 적다.

## 데이터 변경
- 저장소 새 항목 없음. 마이그레이션 없음.
- 동기화 결과(`synced_bookings`)의 에어비앤비 예약에 `ph:"1371"` 한 칸이 늘어난다.
  - 처음 한 번은 모든 에어비앤비 예약 모양이 바뀌므로 저장 1회가 일어난다. 그 뒤로는 바뀔 때만.
  - ⚠ 피드 변화 기록(`feed_changes`)이 이 때문에 "모두 사라졌다 다시 나타남"으로 적히지 않는지 확인할 것
    (비교 기준이 날짜뿐이면 무관 — 구현 때 확인)

## 제약 및 주의사항
- ⛔ **iCal 내보내기(`/ical/…`)에 절대 안 나간다** — 내보내기는 날짜만 쓴다. 구현 후 45개 주소 바이트 동일 확인
- ⛔ 아카이브·알림 기억표·원장 모양 불변 (`uid` 때 정한 원칙 그대로)
- ⚠ **보안**: 예약 목록 주소(`/bookings`)는 비밀번호 없이 누구나 열 수 있다. 여기에 실리면
  주소를 아는 사람은 지금 예약된 도어락 번호를 한눈에 볼 수 있다.
  다만 지금도 호실 목록 주소(`/rooms`)가 에어비앤비 피드 주소를 그대로 주고, 그 피드에 같은 번호가 있다.
  → **새로 열리는 구멍은 아니지만 더 보기 쉬워진다.** 잠금은 이번 범위 밖.
- 웹 조사: 숙박 관리 프로그램(Host Tools)도 같은 방식(전화 끝 4자리)을 기본으로 쓴다.
  10,000가지뿐이라 **퇴실 후 번호를 바꾸는 것**이 전제다 — 도어락 쪽 운영 문제라 앱 범위 밖.

## 청소앱 — 사장님 원칙 (10/16)
> 비밀번호는 원래 호스트와 게스트만 알아야 한다. 그런데 실제로는 청소 인력(주로 알바, 사람이 바뀜)이
> 도어락 번호 세팅까지 해준다. → 청소앱에는 **체크인·체크아웃 당일에만** 보여야 하고,
> 앞으로 올 예약 번호가 미리 다 보이면 안 된다.

### ⚠ 지금 이미 있는 구멍 (10/16 확인)
청소앱은 에어비앤비 **원본 피드를 그대로** 받는다 (`/?url=<에어비앤비 주소>`, fix 없음).
그 원본에 **앞으로 올 모든 손님의 끝 4자리가 이미 들어 있다.** 화면에 안 그릴 뿐이다.
청소앱은 로그인 없이 열리고(주소만 알면 됨), 휴대폰 개발자 도구를 다룰 줄 알면 지금도 볼 수 있다.
→ "화면에서만 숨기기"로는 원칙을 못 지킨다.

### 3단계 안
| 단계 | 하는 일 | 막는 것 | 못 막는 것 |
|---|---|---|---|
| ① 화면만 가림 | 청소앱이 당일 아닌 번호를 안 그림 | 그냥 앱을 쓰는 사람 | 데이터엔 다 들어 있음 |
| ② 서버에서 거름 | 워커가 청소앱용 에어비앤비 피드에서 전화번호 줄을 **지우고**, 오늘이 입실·퇴실일인 예약 번호만 붙여 준다 | 청소앱이 받는 데이터에서 앞날 번호가 **아예 사라짐** | 피드 원주소를 알아내 직접 여는 사람 |
| ③ 원주소 숨기기 | 청소앱이 받는 호실 목록에서 피드 원주소를 빼고 호실 이름으로만 요청 | 원주소 노출 | — |

- 권장: **②까지 이번에**. ③은 이 기능과 별개로 지금도 열려 있는 구멍이라 **따로 작업**.
- '당일' = 한국 시간 0시~24시. 판정은 워커 한 곳 (#2, #30 — `toISOString` 금지)

## 청소앱 결정 (10/17)
- **②단계**(서버에서 거름) — 사장님 원칙 "미리 다 보이면 안 된다"를 지키는 유일한 길이라 Claude 가 정함
- 교대 날: **나가는 손님 · 들어오는 손님 번호 둘 다** 보인다 (나가는 번호로 문 열고, 들어오는 번호로 바꾼다)
- 예약앱은 제한 없음 — 모든 날짜·모든 번호 그대로 (사장님 전용)

- 청소앱에서 **손으로 넣은 비번**(부킹·트립 손님 등)도 **똑같이 당일만** (10/17)

### ⚠ 정정 (10/17) — ②만으로는 '기술 있는 사람'까지는 못 막는다
워커 주소는 로그인 없이 열린다. 청소앱이 안 받아도, 그 주소를 아는 사람은
예약앱이 쓰는 길(`/bookings` — 자동 번호가 실릴 곳, `/extra` — 손 입력 비번 서랍)을 직접 열 수 있다.
| 이번 작업 | 막는 사람 |
|---|---|
| 청소앱 화면 당일만 + 청소앱이 받는 데이터에서 앞날 번호 뺌 | **앱만 쓰는 보통 알바** |
| (별도) **예약앱 전용 열쇠** — 번호가 나가는 길마다 열쇠 검사, 청소앱엔 당일분만 | 개발자 도구 다루는 사람까지 |
- 별도 작업은 `/rooms`·원본 프록시·`/extra`·`/bookings` 를 함께 잠가야 해서 크다. 지금도 열려 있는 구멍이다.
